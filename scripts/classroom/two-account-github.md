# 두 GitHub 실계정 협업 시험

이 하니스는 기존 `.local/github-live` 시험과 분리되어 있습니다. 운영 서비스·원본 저장소·기존 실검증 DB는 변경하지 않습니다.

## 준비와 읽기 전용 확인

두 계정이 로컬 GitHub CLI에 이미 로그인되어 있어야 합니다. 작성자는 `greatsong`(숫자 ID `6792460`)으로 고정하며, 검토자는 명령 인자로 지정합니다. `gh auth switch`는 사용하지 않습니다. 자식 `gh` 프로세스의 공통 환경 토큰을 제거한 뒤 `gh auth token --hostname github.com --user ...`로 각 계정의 기존 인증을 읽고 `/user`에서 숫자 신원을 확인합니다. 토큰은 메모리에만 보관합니다.

프로젝트 폴더에서 실행합니다.

```sh
node scripts/classroom/two-account-github.mjs --check --reviewer greatsong-danggok
```

`--check`가 기본입니다. 계정 아이디를 생략하면 추측하거나 로그인하지 않고 선행 조건을 안내합니다. 이 명령은 두 계정의 신원, 고정 시험 저장소의 ID·비공개 여부·소유자·이름, 두 계정의 `pull`·`push` 역할, 동일한 `main` SHA만 읽습니다. DB·상태 파일을 만들거나 GitHub에 쓰지 않습니다. 초대·권한 변경·로그인도 수행하지 않습니다.

허용 저장소는 `greatsong/vpylab-private-classroom-e2e-20261028`, 숫자 ID `1436391183`으로 고정됩니다. 비공개 접근과 쓰기 역할이 모두 있어야 실시험을 시작할 수 있습니다. 저장소 역할 확인만으로 세부 토큰의 PR 리뷰 쓰기 범위를 보장하지는 않습니다. 실제 POST 거절은 원문 오류·인증값을 출력하지 않고 중단합니다.

## 실제 협업 시험

이미 완료된 기록을 보면서 직접 테스트하려면 프로젝트 폴더에서 다음을 실행합니다.

```sh
node scripts/classroom/serve-two-account.mjs
```

4063번 프론트엔드와 4064번 API를 열고 기존 두 계정의 근거·피드백을 보존합니다. 로컬 화면의 학생 가·학생 나·선생님 역할로 확인합니다. GitHub에 실제 연결되어 있어 Issue·PR 제출은 고정 비공개 시험 저장소에 반영됩니다. 기존 생성·리뷰·승인 시나리오는 반복하지 않습니다. 종료는 `Ctrl+C`입니다. 동시 `--run` 실행은 같은 잠금으로 차단합니다.

```sh
node scripts/classroom/two-account-github.mjs --run --reviewer greatsong-danggok
```

이 명령은 GitHub에 실제 시험용 제안 브랜치와 열린 PR을 만들고, 두 번째 계정으로 `COMMENT`와 `APPROVE` 리뷰를 각각 작성합니다. Git 객체·고유 제안 브랜치 생성은 PR에 필요한 범위로 제한됩니다. `main` 변경·병합·PR 종료·Issue 생성·권한 변경은 허용하지 않습니다. 시작과 검토 전후에 PR 작성자, `head SHA`, 대상 저장소, 열린 상태, 보존된 `main SHA`를 확인합니다.

로컬에서는 실제 서비스의 저장본·PR 제출·학습 기록 수집·학생별 근거·피드백 API를 사용합니다. 새 SQLite DB와 상태는 `.local/github-two-account/`에 저장하며 디렉터리 권한은 `0700`, DB·상태 파일은 `0600`입니다. `--run`은 로컬 API 포트 `4064`를 사용하고 시험 후 종료하며 프론트엔드를 시작하지 않습니다. 직접 화면을 사용할 때는 위의 별도 `serve-two-account.mjs` 명령을 실행합니다. 결과와 PR URL은 `.local/github-two-account/state.json`에 보존됩니다.

확인 항목:

- 검증한 두 GitHub 숫자 ID를 합성 학생 가·나에 `github_cli_test` 출처로 명시 연결.
- 학생 가의 확정본에서 생성한 PR의 중복 제출 방지.
- 학생 나의 COMMENT·APPROVE가 실제 다른 숫자 작성자 ID와 같은 `head SHA`를 가졌는지 확인.
- 실제 PR·리뷰 수집과 반복 수집 시 근거 ID 중복 방지.
- 학생 가의 PR과 학생 나의 리뷰가 각자의 개인 근거에 귀속되는지, 상대의 개인 근거 접근이 차단되는지 확인.
- 두 학생 각각의 교사 비공개 기록·개별 피드백·팀 피드백을 생성하고 `detail`·`export`·`learning` 응답의 공개 범위 확인.
- 두 토큰이 상태·DB·브라우저 API 응답에 들어가지 않는지 확인.

## 응답 유실과 재개

같은 디렉터리의 `run.lock`으로 동시 실행을 차단합니다. 강제 종료 후 잠금이 남으면 먼저 해당 프로세스가 종료됐는지와 상태를 확인해야 합니다. 하니스가 잠금을 자동 삭제하거나 기존 상태를 초기화하지 않습니다.

PR은 서비스의 고유 작업 브랜치로 재조회하며, 기존 PR의 숫자 작성자·코드·부모 SHA·고유 본문 표식을 확인합니다. PR 작업이 이미 한 번 시도되었다면 같은 작업을 자동으로 다시 실행하지 않습니다. 기존 PR을 재발견하지 못하면 멈춥니다.

리뷰는 전송 전에 `sending`을 저장하며 숫자 작성자·SHA·상태·고유 본문 표식이 일치하는 실제 리뷰만 재사용합니다. 응답 유실 후 리뷰를 찾지 못하거나 이미 거절된 전송이면 자동 재전송하지 않습니다. 교사가 원문과 상태를 확인해야 합니다. 상태를 삭제하여 새 시험으로 취급하는 작업은 중복 생성을 일으킬 수 있습니다.

이미 완료된 로컬 단계를 재사용하는 경우 최초 완료 기록을 유지합니다. 재실행이 과거 모든 검사나 실제 교실 수업을 새로 검증했다는 뜻은 아닙니다.

## 검증 범위와 로컬 테스트

GitHub CLI의 실제 두 계정을 합성 학생에 명시 연결하는 시험입니다. Supabase GitHub OAuth, GitHub App 설치·설치 토큰, Webhook 실수신, 조직 브랜치 보호, 학교 네트워크·실제 학생 사용성은 별도입니다. `installationId: 1`은 로컬 테스트용 자리표시자입니다. 학습 기록 수집은 기존 서비스의 제한된 페이지·최근 기록 범위를 사용하며 활동 수가 사고력·성적을 뜻하지 않습니다.

외부 API·CLI 인증을 사용하지 않는 모의 검사는 다음과 같습니다. 전체 흐름 한 건은 임시 디렉터리의 SQLite와 localhost 임시 포트를 사용하고 종료 후 정리합니다. 제한된 샌드박스에서는 localhost 포트를 여는 실행 권한이 필요할 수 있습니다.

```sh
node --check scripts/classroom/two-account-github.mjs
node --test scripts/classroom/two-account-github.test.mjs
```

현재 모의 테스트는 12개입니다. 사전 조건, 서로 다른 신원·권한, 인증 오류 비노출, 저장소 쓰기 범위, 리뷰 응답 유실·중복 재전송 차단을 검사합니다. 마지막 검사는 실제 서비스 API와 모의 GitHub를 연결한 전체 경로에서 PR 1개·리뷰 2개, 학생별 귀속, 6개 피드백 공개 범위, 재개 시 외부 쓰기 0회를 확인합니다. 이 결과는 실제 두 계정 시험의 통과를 대신하지 않습니다.
