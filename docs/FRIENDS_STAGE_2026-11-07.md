# 프렌즈·3D 무대·완제품 캐릭터 — 2026-11-07

## 바뀐 화면과 교육 코드

- 첫 화면의 만두·손전등·공구상자·분홍 친구 옆에 **프렌즈** 선택을 추가했습니다. 네 친구가 서로 다른 박자로 6초 동안 통통 뛰고 멈춥니다. `통통 튀기`로 다시 재생합니다. 모션 감소 설정에서는 정지합니다.
- 각 캐릭터는 하나의 독립된 `compound`입니다. 프렌즈 전체는 `friends` Python 목록으로 다룹니다. 목록 안의 각 `friend.pos`를 따로 움직일 수 있습니다. 전체를 한 compound로 합치면 개별 움직임이 사라지므로 그렇게 합치지 않았습니다.
- `프렌즈, 내 코드로 만들기`는 `/tutorials/welcome-friend?step=friends`로 연결됩니다. `make_dumpling`, `make_flashlight`, `make_toolbox`, `make_kirby` 함수가 각각 완제품을 반환하고, `origin`·`scale`로 재사용합니다. 인공 지능은 사용하지 않습니다.
- 분홍 친구의 눈을 크게 만들고 몸 표면 방향에 맞췄습니다. 마지막 눈 수정은 흰 반사광의 크기와 위치만 조정했습니다. 다른 세 친구의 입은 25개 접합점의 작은 구와 원기둥을 이어 만든 매끄러운 반원 곡선으로 바꿨습니다.
- 실제 Three.js 장면에 둥근 입체 무대, 두 스포트라이트, 조명 기구, 투명 3D 빛기둥과 그림자를 배치했습니다. 만두는 금빛, 손전등은 파랑·레몬빛, 공구상자는 살구·청록빛, 분홍 친구는 분홍·보랏빛, 프렌즈는 파랑·살구빛입니다. 무대 조명 버튼으로 끌 수 있습니다. SVG 빔이나 CSS 바닥 빛은 사용하지 않습니다.
- 튜토리얼의 조명은 표준 VPython `local_light`입니다. 홈의 장식용 무대·스포트라이트와 동일한 조명 API라고 설명하지 않습니다.

공식 VPython은 curve를 compound에 넣지 못합니다. 따라서 입은 구·원기둥으로 만들고 함께 묶습니다. 근거: [공식 compound 제약](https://www.glowscript.org/docs/VPythonDocs/compound.html#restrictions-on-compounds).

## 공유 HTML에서 발견해 고친 원인

편집기는 compound의 경계 중심과 회전·위치 변경을 처리하지만, 공유 HTML에 포함된 별도 Python 래퍼는 `compound.rotate`가 없고 기본 위치를 원점으로 잡았습니다. 렌더러도 자식의 좌표를 compound 중심 기준으로 바꾸지 않았습니다. 이 상태에서 완제품 인사 코드를 실행하면 오류가 나거나 회전 중심이 어긋납니다.

공유 HTML은 생성된 실제 도형의 경계 중심·크기를 읽고, 부품의 월드 변환을 유지한 채 중심 기준으로 묶도록 고쳤습니다. `axis`·`up`·`rotate`와 `pos` 벡터 변경 콜백을 연결했습니다. `friend.pos = ...` 다음 `friend.pos.x += ...`도 실제 렌더러 좌표에 반영됩니다. 이는 이번 예제에서 확인한 범위이며 모든 VPython API 지원을 뜻하지 않습니다.

## 검증

- 화면과 실제 CPython/VPython 브리지의 부품별 위치·회전·경계, 4개 compound의 독립 움직임과 원위치 복귀를 검증한 7개 검사 통과.
- 최종 전체 클라이언트 검사는 Worker 동시 수를 4로 제한하여 **70개 파일, 792개 검사 모두 통과**했습니다. 앞선 기본 동시 실행에서 Worker 검사 프로세스 하나가 종료됐으므로 해당 파일의 6개 검사 분리 실행과 최종 전체 실행으로 다시 확인했습니다.
- 서버 유틸리티 10개 통과. 린트 오류 0개(기존 LoadingScreen 경고 1개), 빌드 성공.
- 로컬 실제 WebGL/UI 17개 통과: 개별 4종, 프렌즈 움직임의 픽셀 변화, 조명 전환, 인사 재생, 모션 감소, 반응형 메뉴, 영어, WebGL 및 lazy chunk 실패 시 대체 화면.
- 개별 4종+프렌즈의 실제 Pyodide 실행과 공유 HTML 5종, 기존 카메라·compound 공유 HTML 회귀를 확인합니다. 결과 JSON에 실제 통과 범위를 기록합니다. 공유 HTML CDN은 설치된 동일 버전 Three.js·Pyodide로 치환하며, 계정/DB를 쓰지 않습니다.

## Claude 검토와 반영

3-way 스킬의 Claude 읽기 전용 검토를 받았습니다. 첫 시도는 180초 후 종료됐고 같은 사본으로 300초 대기 재시도에서 응답을 받았습니다. Claude는 코드를 실행하지 않았습니다.

| 지적 | 반영/확인 |
|---|---|
| 저장한 위치 참조의 두 번째 수정 누락 | 벡터를 매번 복제하는 콜백 대신, 현재 벡터에서 명령을 보내도록 수정. 전체 위치를 재대입하면 이전 콜백을 해제. 실제 내장 Python 테스트 추가 |
| 생성자 입력 위치 공유 | 일반 객체와 compound 모두 입력 위치 복사 |
| 인사 회전 기준 | Python은 원점을 명시하며 홈과 같은 기준. 사용하지 않는 손 전용 pivot 제거 |
| 빛기둥 방향 | 바닥 높이 변경 시 스포트라이트 target·기구·빛기둥 방향과 길이를 함께 갱신 |
| 상자 axis | 현재 상자에는 axis 지정이 없지만, 미리보기의 상자도 X/up 기저 처리로 통일 |
| 좁은 화면 무대 잘림 | 세로 범위와 함께 가로 최소 반폭 2.05를 확보 |
| sin/cos/pi | 이미 math에서 명시 import. 실제 Python 5개 프로그램으로 확인 |
| 흰색 compound가 부품 색을 지우는지 | 공유 재질 도구는 기본 부품 색에 곱함. 실제 브라우저 캡처에서 각 색 유지 확인 |
| PCFSoftShadowMap | 설치된 Three.js 0.183.2 소스의 폐기 경고를 확인하고 PCFShadowMap으로 교체 |

첫 사본에서 브리지의 data 디렉터리 제외 규칙으로 도형 명세가 빠졌으므로, 최종 재검토에는 도형 데이터·테스트·공유 도구를 루트에 배치한 사본을 제공했습니다. 전체 API의 size·clone 등 추가 구현은 이번 검증 범위로 주장하지 않습니다.

최종 Claude 재검토는 148초에 완료됐으며 새 P1/P2가 없고 이전 지적이 해소됐다는 응답을 받았습니다. 검토자는 코드만 읽었으며 실행 검증은 아래 도구 결과와 별도입니다. 마지막 제안도 반영해 시작 0.3초·끝 0.5초에 점프 높이를 줄이고, 발 아래 여유를 0.05로 늘렸습니다. 사용하지 않는 curve 분기를 제거했습니다.

편집기 API는 이미 벡터 소유자를 추적하는 별도 구현이므로 같은 패치를 덮어쓰지 않았습니다. 대신 생성자 입력 독립성과 저장한 위치 참조의 연속 수정이 실제 Three.js 그룹까지 전달되는 회귀 검사를 추가했고, 환영 도형 검사와 함께 15개 모두 통과했습니다.
