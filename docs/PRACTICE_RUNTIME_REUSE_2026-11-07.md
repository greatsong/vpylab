# 실습 재진입의 Python 준비 지연 개선 — 2026-11-07

사용자 우선순위는 홈 용량 축소보다 실습에 들어갈 때마다 반복되는 준비 지연을 줄이는 것입니다. 홈 번들·Monaco 언어 구성·Service Worker 사전 캐시·팀 저장 구조는 이번 변경 범위에서 유지합니다.

## 원인과 변경

기존에는 `usePyodide`의 마지막 화면 구독이 해제되면 준비된 Worker도 즉시 종료했습니다. 파일이 HTTP/Service Worker 캐시에 있어도 Python VM과 VPython 모듈 초기화는 다시 필요했습니다. 개발 StrictMode의 Effect 재실행도 Worker를 다시 만들었습니다.

- 화면이 떠나면 소리와 입력을 즉시 차단하고, 실행 중인 코드는 협조적 정지를 요청합니다.
- 실행 종료를 확인한 다음 Worker에 `park`를 요청합니다. Python 태스크·오브젝트·이벤트·입력·출력 상태 정리가 끝난 `parked` 응답을 받아야 재사용합니다.
- 정지 또는 정리가 750ms 안에 응답하지 않으면 해당 Worker를 버립니다. 기다리는 새 실습 화면이 있을 때만 새 엔진을 준비합니다.
- 정리된 엔진은 마지막 실습 이탈 후 정리 완료 시점부터 최대 10분 보관합니다. 초기화 중의 짧은 화면 이동과 StrictMode 재구독은 같은 준비 Promise를 공유합니다.
- 참고 자료를 보려고 탭을 숨겨도 보관 기간 안에는 유지합니다. 유휴 만료·계정 변경은 VM 전체를 종료합니다. 배경 타이머가 지연돼도 재구독·탭 가시성 변경·pageshow에서 벽시계 만료를 다시 검사합니다.
- 엔진을 준비하거나 강제 정지 후 복구하는 동안에도 만들기·트레이닝의 편집기와 안내를 유지합니다. 실행은 준비 완료 전까지 막고, 진행률·오류·재시도는 모바일에서도 표시합니다.

## 재사용과 격리 범위

재사용하는 것은 같은 탭·같은 로그인 세션의 Python VM과 로드된 패키지입니다. 새 실행은 기존 `_vpylab_reset_runtime()`과 새 학생 전역 딕셔너리를 사용합니다. 네트워크·저장 API 제한은 유지합니다. `runId`, 종료한 Worker 식별 검사, 보관 요청 토큰과 정리 단계 검사를 통해 이전 화면의 늦은 메시지를 버립니다.

새 전역 딕셔너리는 완전히 새 Python 프로세스와 같지 않습니다. Python 모듈 캐시와 가상 파일시스템은 VM 안에 남을 수 있습니다. 계정 전환에서는 이를 포함한 VM 전체를 버립니다. 별도의 시험 격리 정책을 새로 보장하는 변경은 아닙니다.

10분 동안의 빠른 복귀를 위해 메모리를 유지하는 절충입니다. 비협조적 무한루프, 정리 실패, 유휴 만료, 계정 변경 이후에는 새 초기화가 필요합니다. 새로고침이나 새 탭을 넘어서 엔진을 재사용하지는 않습니다.

후속 탭 보관·오디오·렌더링·대표 콘텐츠 개선과 최종 검증은 [빛과 소리 실습 개선 기록](LIGHT_SOUND_PRACTICE_POLISH_2026-11-07.md)에 정리했습니다. 아래 숫자는 최초 재사용 개선을 검증한 시점의 기록입니다.

## 실제 검증

로컬 Chromium, 로그인 없는 합성 게스트 코드로 확인했습니다. 다음 시간은 같은 실습 → 튜토리얼 → 실습 시나리오의 단일 관측치이며 학교 기기의 p50/p95나 운영 서비스 측정은 아닙니다.

| 조건 | 개선 전 | 개선 후 |
|---|---:|---:|
| 개발 모드의 실습 왕복 준비 시간 | 3,178ms | 101ms |
| 개발 모드의 왕복 누적 Python Worker 생성 수 | 4 | 1 |
| 보관된 production 빌드와 개선 빌드의 왕복 준비 시간 | 2,187ms | 74ms |
| production 왕복 누적 Python Worker 생성 수 | 2 | 1 |

production 실제 브라우저의 6개 시나리오도 통과했습니다.

1. 초기화를 지연시켜도 Monaco에서 코드를 바꿀 수 있고 준비 후 편집기가 교체되지 않음.
2. 실제 Python 반복문·긴 음을 실행하다 화면을 이동해도 오디오 그래프 신호가 정리되고 같은 Worker 재사용. 이 경우 복귀 33ms.
3. 새 화면에서 실행한 코드에 이전 학생 전역 변수 없음.
4. `rate()` 없는 무한루프를 강제 정지한 뒤 새 Worker로 실행 복구.
5. 모바일 크기에서도 런타임 상태 표시.
6. 초기화 실패를 주입해도 편집기를 유지하며 재시도 후 실제 Python 준비 완료.

브라우저 소리 검사는 AnalyserNode의 신호를 확인한 것이며 물리 스피커 청취 검사가 아닙니다. OAuth 계정 변경·유휴 만료·탭 숨김·늦은 메시지는 단위/통합 검사이며 실제 외부 계정 로그인 검증으로 표현하지 않습니다.

- 전체 클라이언트: 80개 파일, 851개 검사 통과.
- 최종 엔진/Worker/hook 검사: 44개 통과.
- 별도 교실 계정 경계 및 런타임/hook 검사: 36개 통과.
- 변경 파일 ESLint와 공백 오류 검사 통과.
- 일반·교실·교사 연수·LAN production 빌드 통과. 기존 큰 청크 경고는 남아 있습니다.
