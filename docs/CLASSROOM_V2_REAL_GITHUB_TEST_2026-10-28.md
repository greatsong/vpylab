GitHub 토큰은 서버 프로세스 메모리에서 사용했습니다. DB와 WAL·SHM, 상태 파일, 검사한 브라우저 API 응답에 토큰 문자열이 포함되지 않았음을 확인했습니다. 이 검사는 GitHub CLI 자체의 기존 자격 증명 저장 방식을 검증한 것은 아닙니다.

## 실제로 확인한 동작

| 영역 | 확인한 결과 |
| --- | --- |
| 연결·가져오기 | 저장소의 숫자 ID·소유자·비공개 여부를 확인하고, 실제 SHA에 대응하는 Python 파일을 가져왔습니다. 가져오기만으로 팀 코드를 바꾸지 않았습니다. |
| 질문→Issue | 저장한 학생 질문을 실제 Issue로 보냈으며 동일 요청의 재처리로 중복 Issue가 생기지 않았습니다. |
| 팀 저장본→PR | 확정한 팀 코드로 고유 브랜치와 PR을 만들었습니다. PR 생성 단계에서 main과 다른 파일을 보존했습니다. |
| 검토·대화 | 실제 COMMENT 리뷰, Issue 댓글, 코드 줄 의견을 작성하고 다시 수집했습니다. 같은 계정의 자기 PR APPROVE 요청은 GitHub가 HTTP 422로 거절했습니다. |
| 이력 보존 | 반복 수집 시 동일 근거 ID를 유지하고, 댓글 수정 전후 본문을 각각 보존했습니다. |
| 외부 병합·충돌 | 테스트 PR을 병합한 뒤 다시 가져와도 개인 초안과 로컬 팀 버전이 유지됐습니다. 이후 테스트용 외부 커밋을 추가하고 오래된 SHA로 제출한 PR 작업이 충돌로 차단됨을 확인했습니다. |
| 학생별 근거 | 실제 숫자 GitHub ID의 기록은 학생 가에 귀속되고 학생 나에게 섞이지 않았습니다. 다른 학생의 개인 근거 조회는 HTTP 403으로 차단했습니다. 숫자 작성자 ID가 없는 커밋은 추측하여 연결하지 않았습니다. |
| 교사 기록·피드백 | 실제 PR·리뷰 근거 2개를 연결한 비공개 기록·대상 학생 피드백·팀 피드백을 저장했습니다. 같은 요청 키의 재전송은 기존 결과를 반환했습니다. |
| 공개 범위 | detail·export·학생별 learning 응답에서 교사 개인 기록과 학생별 피드백의 공개 범위를 검사했습니다. 브라우저에서 학생 가에게 개별 피드백이 보이고 교사 개인 기록은 제외됨을 확인했습니다. 학생 나에게는 학생 가의 개별 피드백·교사 개인 기록이 모두 보이지 않고 팀 피드백만 표시됐으며, GitHub 계정 미연결 안내도 확인했습니다. |
| 권한·근거 격리 | 관찰자의 로컬·GitHub Issue·제안·기록 동기화 쓰기를 차단했습니다. 다른 프로젝트의 근거를 피드백에 참조하면 HTTP 422로 거절했습니다. 관찰자 시험 후 편집자 역할 복구를 실제 조회로 확인했습니다. |
| 재시작·복구 | 서버 재시작 후 근거·피드백·개인 초안이 유지됐습니다. 실제 시험 DB를 백업하고 별도의 임시 DB에 복구하는 리허설을 통과했습니다. |

외부 병합과 충돌을 만들기 위한 main 변경은 **테스트 도구가 이 비공개 시험 저장소에서만** 수행했습니다. 교실의 PR 제출 기능이 main을 직접 바꾸거나 PR을 자동 병합하는 동작은 아닙니다.

## 검증 도구에서 발견하고 고친 문제

1. 학생 나의 역할 복구 요청이 초기 편집자 추가 요청과 같은 idempotency 키를 사용해, 재생된 성공 응답만 받고 실제 역할이 관찰자로 남았습니다. 전환·복구 각각의 고유 키를 사용하도록 고치고 복구 후 GET으로 실제 역할을 단언했습니다. 학생 나를 편집자로 복구한 뒤 관련 검사를 다시 실행했습니다.
2. 서버 재시작 직후 검증 도구가 종료된 keep-alive 소켓을 재사용하여 `fetch failed`로 중단됐습니다. 로컬 HTTP 검사 연결을 요청마다 종료하도록 고친 뒤 재시작 검사를 다시 통과했습니다.

이 두 건은 검증 도구의 오류와 수정 사항입니다. 실패한 실행을 정상 통과로 집계하지 않았으며, 수정 후 완료한 결과를 보존했습니다.

## 직접 확인하는 방법

이미 로컬 화면이 열리면 [검토 화면](http://127.0.0.1:4053/classroom.html#/projects/31136e28-5259-4992-b446-9ebe80dee3a9/process)에서 바로 확인할 수 있습니다. 서버를 다시 시작할 때는 저장소 루트에서 다음을 실행합니다.

```sh
node scripts/classroom/live-github.mjs --serve
```

`--serve`는 보존한 DB·상태로 로컬 교실을 엽니다. 검증 시나리오를 다시 수행하지 않지만 **실제 저장소 연결 상태**이므로 UI에서 제출하거나 대기 작업이 처리되면 시험 저장소에 쓸 수 있습니다. 기존 GitHub CLI 로그인이 필요하며 4053·4054 포트를 사용합니다. `Ctrl+C`로 종료합니다.

자동 실검증을 수행·재개하는 명령은 다음과 같습니다. 실제 시험 저장소의 Issue·PR·댓글·커밋을 만들거나 수정·병합할 수 있습니다.

```sh
node scripts/classroom/live-github.mjs --run
```

스크립트는 고정된 숫자 ID의 비공개 테스트 저장소만 허용합니다. 상태 파일을 유지해 이미 완료한 단계를 재사용하며, 임의로 상태 파일을 지우고 새 시험처럼 실행할 필요는 없습니다. 일반 모의 교실의 `npm run dev:classroom`과는 DB·포트가 분리되어 있습니다.

화면에서는 다음을 확인합니다.

1. 선생님으로 **GitHub 과정**에서 원문 링크, 작성자, 수집 경로와 학생 가의 근거를 확인합니다.
2. 학생 가에게 연결한 근거·관찰·다음 질문과 교사 개인 기록의 공개 범위를 확인합니다.
3. 학생 가로 전환해 전달된 피드백을 확인하고, 교사의 개인 기록이 표시되지 않는지 봅니다.
4. 학생 나로 전환해 학생 가의 개별 피드백과 개인 근거가 섞이지 않는지 확인합니다. 팀 피드백은 두 학생 모두 볼 수 있습니다.
5. 제작·실험에서 기존 수업 자료, 3D 실행과 소리 기능을 함께 살펴봅니다. 이 시험 수업은 AI 미사용이며 AI 사용 수업도 별도 정책으로 지원합니다.
