사용자가 승인한 네 개선을 반영했습니다. 기존 작업을 보존했습니다. 후속 사용자 배포 지시로 커밋 `937eb95`를 main에 반영했고 Vercel·Railway와 GitHub CI 7개 항목의 성공, 운영 브라우저 12개 검사를 확인했습니다. [운영 배포 증거](collaboration/light-sound-production-2026-11-07.json)를 참고하세요.

## 반영한 동작

1. **참고 자료를 볼 때도 최대 10분 보관**: 실습을 나가면 학생 상태·입력·음원을 정리하지만 준비된 Python VM은 보관합니다. 탭 숨김만으로 버리지 않습니다. 유휴 만료를 타이머와 벽시계로 확인하며 재구독·가시성 변경·bfcache pageshow에서 만료를 재검사합니다. 계정 변경·정리 실패·비협조적 코드는 기존 폐기·복구 규칙을 따릅니다.
2. **음악 예약과 음 표시**: 시퀀스와 BGM은 AudioContext.currentTime 기준 절대 시각으로 예약합니다. 25ms마다 약 120ms 앞까지 준비하며, 긴 지연 뒤 지난 음을 한꺼번에 재생하지 않습니다. envelope와 source.start/stop이 같은 시각을 쓰고, 정지·음소거는 미래 예약 소스도 정리합니다. 오디오 재개가 늦어져도 첫 예약음을 수명 타이머가 먼저 버리지 않게 했습니다. 현재 음은 가능한 경우 getOutputTimestamp로 출력 시각을 보정하고, 지원하지 않으면 currentTime으로 계산합니다. UI 실행 확인음은 작품의 음 표시에서 제외합니다. 표시 갱신을 GPU 프레임과 분리해 짧은 음이 렌더 대기에 묶이지 않게 합니다.
3. **정지 장면 GPU 그리기 감소**: 명령·카메라 위치/방향/투영·리사이즈·테마·축 변화에 즉시 그립니다. 객체가 캔버스를 옮기면 출발·도착 화면 모두 즉시 갱신합니다. 나머지 비동기 변경의 누락에 대비한 2Hz 보정 그리기도 남깁니다. 카메라와 입력 갱신은 유지합니다. GPU 렌더 횟수를 줄인 것이며 모든 CPU 작업이나 전력 사용이 사라진다는 뜻은 아닙니다.
4. **기존 튜토리얼에 대표 작품 두 개**: 키보드 우주 악기(space-instrument), 빛나는 아르페지오(glow-arpeggio)를 추가했습니다. 완성작 체험→한 음 변경→내 작품 단계와 예상·수정·설명·친구 시험을 제공합니다. 자동 작품 연주는 없고 버튼·키를 눌러 연주합니다. 키보드 악기는 터치용 네 버튼도 제공합니다. play_note는 VPyLab 확장임을 명시했습니다.

임의의 학생 3D 애니메이션 전체를 음악과 샘플 단위로 동기화하는 API를 새로 만든 것은 아닙니다. Python의 sleep 기반 장면 변화와 음악 시퀀스의 예약 시각은 구분됩니다. 배경 탭에서 장시간 타이머가 멈추면 밀린 음을 건너뛰므로 완전한 배경 음악 재생을 보장하지 않습니다. Bluetooth·Safari/iOS·실제 학교 저사양 기기 검증은 남아 있습니다.

## 검증

- 전체 클라이언트: 85개 파일·879개 검사를 검증했습니다. 전체 실행에서 문서 예제 묶음 1건이 병렬 빌드와 겹쳐 30초 제한에 걸렸고, 빌드 종료 후 문서·캔버스 15개 검사를 분리 실행해 모두 통과했습니다. 테스트 제한은 바꾸지 않았습니다. 기존 교실 오디오 테스트도 독립적인 AudioContext 시계를 전진시키도록 수정했습니다.
- 변경 파일 ESLint와 공백 검사 통과.
- 일반·교실·교사 연수·LAN production 빌드 통과. 기존 큰 청크 경고는 남아 있습니다.
- 실제 Chromium 배포 빌드에서 대표 작품·음 표시·키/버튼·모바일·절대 오디오 예약·정지 장면의 6개 시나리오 통과.
- 기존 초기화 지연·이탈 정리·새 전역·강제 정지·모바일 상태·재시도 6개 브라우저 시나리오도 통과.
- 정지 장면은 1.1초에 WebGL draw 2회, 카메라 조작 때는 40회 관찰했습니다. 단일 로컬 소프트웨어 GPU 관측이며 학교 기기의 FPS·전력 벤치마크가 아닙니다.
- 실제 시퀀스 두 번째 음은 약 119ms 앞에 예약됐고 0.2초 간격의 절대 시각이 맞았습니다.
- 브라우저에서 다른 탭을 열었지만 headless의 visibilityState는 visible이었습니다. hidden·만료·계정 경계는 단위검사에서 확인했습니다. 실제 탭 숨김을 이 브라우저 검사에서 검증했다고 표현하지 않습니다.
- 물리 스피커 청취는 하지 않았습니다. 오디오 그래프·예약 시각·표시와 이전 AnalyserNode 기반 정리 검사를 사용했습니다.
