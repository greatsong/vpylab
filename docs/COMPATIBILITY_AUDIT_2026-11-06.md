# VPyLab 호환성 분석과 개선

> 최신 후속 검토: [도형 AI·compound·카메라·학습 이동 보고서](SHAPE_CAMERA_UX_REVIEW_2026-11-07.md). 이 문서의 이전 검증 수치와 구별해 보세요.


> 후속 개선: 다중 canvas, vertex UV·동적 메시, helix.size, mouse(), 카메라 초기화는 [창작 자료·호환성 후속 보고](CREATIVE_LEARNING_AND_VPYTHON_2026-11-06.md)에서 개선했습니다. 아래 657개 검사와 남은 문제 표는 이번 후속 수정 전 기록입니다. 최신 검증 기록을 함께 보세요.

2026년 11월 6일 현재 소스 기준입니다. GlowScript와 설치형 VPython의 공개 예제·문서·공식 API 규칙, VPyLab 자체 자료와 가져온 작품을 대조했습니다. 공식 VPython 모듈을 별도 실행해 화면을 전수 비교한 결과는 아닙니다.

이번에는 실제 API 누락과 원본 코드 문제를 구분했고, 예외가 없더라도 값이나 조작이 다른 문제를 찾아 수정했습니다. 전체 호환성을 달성했다는 뜻은 아닙니다. 운영 배포는 이번 작업에 포함하지 않았습니다.

## 수정한 엔진 문제

| 문제 | 원인 | 개선과 확인 |
|---|---|---|
| 인자 없는 버튼 함수가 실행되지 않음 | 모든 이벤트 함수에 무조건 `h(info)` 호출. `def run_button():`에는 인자가 하나 많음 | 함수 서명을 먼저 검사해 0개/1개 인자를 구분. 함수 내부의 TypeError를 인자 오류로 오해해 두 번 실행하지 않음. 실제 군집화 RUN으로 540건·5회 분류 완료 |
| 메뉴 콜백에서 `.selected`, `.index`를 읽지 못함 | 실제 위젯 대신 `_EventInfo`만 전달 | 위젯 ID와 실제 객체를 연결하고 값을 갱신한 뒤 전달. 실제 메뉴 변경과 슬라이더 이동 확인 |
| 콜백 오류가 검사에서 숨겨짐 | 동기 콜백 예외를 출력만 하고 삼킴 | 기존 비동기 태스크와 같은 오류 전달 경로로 올림. 본문 TypeError·async ValueError·태스크 회수 회귀 검사 |
| 방향키를 눌러도 원작 게임이 반응하지 않음 | DOM의 `ArrowUp`을 그대로 전달. 공식 VPython 코드는 `up`을 비교 | `evt.key`와 `keysdown()`을 공식 이름으로 정규화. 원래 DOM 이름은 `evt.raw_key`로 제공. 내장 예제·차시·API 문서 정정. 실제 뱀의 y 증가와 테트리스 블록 4개의 좌우 이동·복귀 확인 |
| `color.green`, `color.purple` 값 불일치 | 각각 `(0,0.8,0)`, `(0.5,0,0.5)`로 구현 | 공식 `(0,1,0)`, `(0.4,0.2,0.6)`으로 정정. 한글 별칭·연결된 미션 채점·공유 HTML까지 함께 정정하고 실제 내보내기 API 비교 |
| 그래프의 `plot(pos=...)` 등 실패 | Python 래퍼의 허용 인자 형식 부족 | 점 한 쌍·점 목록·pos=/data=·여러 x,y 인자 지원. 기존 x목록/y목록 형식도 보존 |
| 점 그래프 반지름 변경 실패 | `.radius` 속성 없음. 속성을 단순 추가해도 렌더러로 전달되지 않음 | 반지름과 지름의 관계를 구현하고 `graph_series_update`를 브릿지·Canvas2D까지 연결. 실제 Canvas arc의 반지름·색상 확인 |
| 그래프 데이터 대입이 그림을 바꾸지 않음 | 임의 Python 속성으로만 저장 | `.data` 대입은 기존 점을 비우고 교체하며 Python 읽기 값도 동기화. `get_selected()`는 삭제된 그래프를 반환하지 않음 |

공식 규칙 근거: [키 입력](https://www.glowscript.org/docs/VPythonDocs/key.html), [색상](https://www.glowscript.org/docs/VPythonDocs/color.html), [그래프](https://www.glowscript.org/docs/VPythonDocs/graph.html).

### 키 이름 변경의 영향

기존 VPyLab 내장 자료가 사용하던 `ArrowLeft` 등의 표기를 공식 `left` 등으로 바꿨습니다. 저장된 사용자 코드에서 `evt.key == 'ArrowLeft'`를 비교한다면 `evt.key == 'left'`로 정정해야 합니다. DOM 이름 자체가 필요한 경우 `evt.raw_key`를 사용할 수 있습니다. 사용자 DB의 저장 코드는 자동 수정하지 않았습니다.

## 원본을 보존하고 수정한 실행용 코드

| 작품 | 원인 구분 | 실행용 수정 |
|---|---|---|
| 경사하강법 | GlowScript의 확장 range와 Python 기본 range의 차이 | 소수 간격의 range 세 곳을 `arange`로 변환. 기본 Python range는 그대로 유지 |
| 군집화 | 원본의 `else if`, 색상 인자의 잘못된 괄호 위치. 실행 시 초기 선택·동률·빈 군집 문제도 존재 | Python 문법과 인자 위치 정정, 기본 축 선택, 동률 시 일관된 배정, 빈 군집 중심 유지. 원본 코드와 변경 이유 별도 보존 |
| 과학 연수 작품 | 함수 자체가 없는 것이 아니라, 함수 정의 전 이름을 사용 | `speed_f` 정의를 슬라이더 생성 앞으로 이동. 위젯 값 변경은 엔진에서 함께 수정 |
| 테트리스 | 실수 좌표를 리스트 인덱스로 사용. 벽을 중복 생성 | 인덱스에 int 사용. 원본 벽의 영역과 같은 벽 4개로 상자 4,896개 대체. 키 문제는 엔진 수정 |
| 스네이크 | Python 3.12의 randint는 실수 경계를 받지 않음. scene.range는 실수 | 먹이 좌표 생성의 정수 경계를 명시. Python 3.11에서는 이 오류를 놓칠 수 있었음. 키 문제는 엔진 수정 |

원본을 고쳐 덮어쓰지 않았습니다. `client/public/projects/glowscript/*.json`의 `source`와 `sha256`은 보존하고, `code`·`adaptations`에 실행용 수정본과 이유를 기록했습니다. 작품 상세 화면에서 원본과 수정 이유를 볼 수 있습니다.

## 검사 체계에서 고친 문제

- 33개 작품과 4개 체험을 지속 검사에 포함했습니다. 알려진 원본 오류 5개도 별도 재현해 수정본의 통과와 혼동하지 않습니다.
- 테스트는 Pyodide 0.27과 같은 Python 3.12를 우선 사용합니다. 기존 3.11 실행만으로는 스네이크의 정수 경계 오류를 발견하지 못했습니다.
- 위젯을 등록한 뒤 실제 이벤트를 보내는 테스트를 추가했습니다. 함수를 직접 호출하는 검사만으로는 인자 수와 위젯 객체 전달 결함을 발견하지 못했습니다.
- 실제 게임 조작은 오류 여부뿐 아니라 좌표 변화로 확인했습니다.
- 엔진·코퍼스 해시가 다른 정적/브라우저/임시 shim 결과는 자동으로 합치지 않습니다. 과거 결과를 현재 통과율처럼 표시하지 않습니다.
- 인자를 생략한 문서 표기와 빈 원본은 앱 결함으로 세지 않습니다. 검사 자체 오류는 숨기지 않습니다.

## 남은 문제와 우선순위

| 우선 | 항목 | 원인·현재 상태 | 다음 검증 기준 |
|---|---|---|---|
| P1 | 다중 canvas | 현재 여러 canvas()가 같은 scene을 반환. 경사하강법도 세 캔버스를 만들지만 VPyLab은 하나로 합쳐 보임 | 객체·카메라·위젯·그래프를 캔버스별로 분리하고 원작과 비교. 실행 통과와 화면 일치를 구분 |
| P1 | vertex.texpos와 Rug | 정점 생성자가 텍스처 좌표를 받지 않음. 단순히 인자를 무시해 통과시키면 원작의 질감이 사라짐 | UV 좌표·텍스처 렌더링·정점 변경 전파까지 함께 구현하고 실제 화면 확인 |
| P2 | helix.size와 Stonehenge | 나선의 size 속성 없음 | 길이·직경·axis 및 Three.js 지오메트리 갱신의 일치 검사 |
| P2 | 일부 문서의 scene.mouse() | 현재 mouse는 속성 객체이며 호출형 조각 두 개가 TypeError | 구형 문서와 현행 VPython 규칙 대조 후 호환 별칭 또는 문서 조각 정정 |
| 환경 차이 | MathJax, Date | JavaScript 전역을 참조하는 Web VPython 예제 | Python 변환본 또는 해당 기능 전용 연결. 기본 Python 이름을 임의로 추가해 통과 처리하지 않음 |
| 환경 차이 | ipywidgets 5개 데모 | Jupyter 호스트 기능을 사용 | 노트북 호스트와 VPyLab DOM 위젯 연결을 별도 범위로 판단 |
| 의도적 제약 | get_library, read_local_file, download | Worker의 네트워크·로컬 파일 경계와 관련된 기능 | 지원 범위를 정의한 뒤 별도 구현. 이번에 샌드박스 제한을 완화하지 않음 |
| 실행 제어 | rate 없는 무한 반복 | 협력적 양보 없이 CPU를 점유 | 기존 무응답 중지·Worker 재시작 경로 유지. 예제 오류와 엔진 결함 구분 |
| 표시 차이 | 공유 HTML의 그래프·위젯 등 | 편집기와 독립 HTML의 지원 범위가 같지 않음 | 색상 일치는 이번에 검증했지만 전체 API·화면의 동등성은 별도 검사 필요 |

이 목록은 남은 전체 차이를 다 찾았다는 선언이 아닙니다. 현재 코퍼스와 실제 입력 검증에서 확인된 항목입니다. 예외가 없다는 이유만으로 UV·멀티 캔버스·게임 규칙까지 호환된다고 표시하지 않습니다.

## 재검사

- `npm --prefix client run test:run`: 전체 회귀 검사. `vpython-widget-compat`, `vpython-graph-compat`, `vpython-color-compat`, `glowscript-projects.runtime`에 새 사례가 있습니다.
- `npm run compat:check`: 공식 예제·VPython 데모·문서·수업 자료·33개 작품의 Python 3.12 실행 검사와 요약.
- `node --test scripts/compat/evidence.test.mjs`: 다른 버전의 결과를 섞지 않는 검사.
- 실제 브라우저 관찰은 [실행·입력 결과](collaboration/compatibility-browser-2026-11-06.json)에 있습니다. 이 선택 검사 결과를 전체 636개의 브라우저 통과율로 확대하지 않았습니다.
