## 실제 계정 검증 완료

사용자가 별도 검증 브라우저에서 직접 로그인한 실제 계정을 사용했습니다. 운영 Supabase의 `/auth/v1/user` 응답으로 인증을 확인하고, 실제 UI와 일반 사용자 권한으로 검증했습니다. 관리자 권한·합성 인증·가로챈 DB 응답은 사용하지 않았습니다.

1. 식별 가능한 검증용 원본을 공개 등록했습니다(HTTP 201).
2. 모두의 모듈에서 포크해 계정에 **비공개 파생 기록**이 생성되는지 확인했습니다(HTTP 201). 익명 조회에서는 보이지 않았습니다.
3. 너비·이름·설명을 바꾸고 참고 링크를 추가했습니다.
4. 같은 포크 기록을 공개했습니다(HTTP 200). 원본 ID·제목·제작자 스냅샷과 참고 링크, 수정한 레시피가 보존됐고 익명 공개 목록에서도 조회됐습니다.
5. 내 모듈에서 공개를 내렸습니다(HTTP 200). 계정에는 비공개 기록이 남고 익명 조회에서는 사라졌습니다.
6. 검증용 원본도 UI에서 공개를 내렸습니다(HTTP 200). 최종 원본·파생 기록 2개는 비공개이며 현재 공개 목록에는 검증 항목이 없습니다. 이전 자동 입력 검증 시도의 항목도 비공개로 정리했습니다.

초기 검사에서는 기존 제목에 입력이 덧붙는 자동화 입력 문제와 maybeSingle의 배열 응답을 객체로 읽는 검사 문제가 있었습니다. 검사 도구를 고치고 실제 흐름을 끝까지 다시 확인했습니다. 제품 오류로 잘못 기록하지 않았습니다. 비밀번호·토큰·이메일·계정 ID를 보고서와 캡처에서 제외했습니다.

증거: `docs/collaboration/forge-real-account-2026-11-07.json`. 기존 배포 보고서의 ‘실제 계정 쓰기 미검증’은 이 후속 검증으로 해소됐습니다. 여러 계정 간 교차 권한이나 실제 학생 수업 사용까지 검증했다는 뜻은 아닙니다.

## 도형 호환성에서 발견한 원인과 수정

캐릭터를 실제 Python으로 재현하는 검사에서 기존 구현의 두 누락을 발견했습니다.

- **ellipsoid**: Python 객체에 axis·up 연결이 없어 rotate가 방향을 바꾸지 않았고, 렌더러도 타원체의 방향 갱신을 처리하지 않았습니다. box와 공통인 size·length·height·width·axis·up 규칙을 사용하고, 실제 렌더링은 SphereGeometry에 비균등 배율을 적용하도록 유지했습니다. 공유 HTML에도 크기·축의 길이 동기화, 직접 성분 수정과 clone을 맞췄습니다.
- **ring**: 생성 시 axis를 무시했고, Python의 axis 갱신도 전달하지 않았습니다. TorusGeometry의 기본 법선 +Z를 실제 axis로 돌리도록 생성·갱신을 맞췄고, Python setter·clone과 공유 HTML에 함께 반영했습니다.

고리의 기본 axis는 **vector(1,0,0)**이며 고리 면에 수직인 방향입니다. 이는 [공식 VPython ring 문서](https://www.glowscript.org/docs/VPythonDocs/ring.html)의 의미를 따릅니다. 예전 구현에서 axis를 생략해 정면 원으로 보였던 코드는 방향이 달라집니다. 정면 원을 의도하면 `axis=vector(0,0,1)`을 명시하세요. 내장 ring 문서의 설명·인자·예제에도 반영했습니다.

내장 미션·예제의 고리 코드는 축을 명시하고 있었습니다. 원본 33개 중 `gs2024-16`의 두 고리는 axis를 생략하고 있습니다. 그 원본과 학생의 저장 코드를 자동 수정하지 않았으며, 표준 기본 방향을 적용합니다. 공개 원본의 보존과 호환성 수정은 구분합니다. 감사 결과는 `ring-axis-audit-2026-11-07.json`에 남겼습니다.
