## 판단

**`beg-shapes-4`를 출발점으로 하는 작은 팀 프로젝트는 입문 수업에 적절합니다.** 새 문법을 추가하지 않고 좌표·크기·색의 변경 이유를 비교할 수 있습니다. 개인 초안, 변경 제안, 다른 학생의 검토, 버전 충돌 방지, 교사 개별 피드백이라는 기본 도구도 있습니다.

다만 완성 예제를 실행하고 팀 버전으로 저장하는 것만으로 협업 학습이 성립하지 않습니다. 원문과 달라진 기여, 비교한 조건, 동료 의견을 반영한 이유를 교사가 확인해야 합니다. 현재 구현은 이 경로의 학습목표·편집 범위·도움 축소를 자동 관리하지 않으며, 편집자가 동료 검토 없이 직접 팀 버전을 저장하는 것도 허용합니다. 따라서 **현재는 교사가 단계와 제출 규칙을 함께 운영해야 하는 경로**로 판단합니다.

## 공동 문제와 작은 변경

팀 문제는 **“색만으로 구분하기 어려운 상황을 상상하고, 위·가운데·아래의 위치와 크기 차이로 구분할 수 있는 안내등 시안을 만들자”**로 정합니다. 실제 교통 시설의 적합성이나 장애 접근성 인증을 주장하는 과제가 아닙니다. 화면에 만든 시안을 읽고 설명하는 연습입니다.

성공 기준은 ① 세 공이 위·가운데·아래 순서를 유지한다 ② 한 번에 한 종류의 조건을 바꾼 두 시안을 비교한다 ③ 바꾼 숫자와 관찰 결과를 각각 설명한다 ④ 동료의 질문 한 가지에 근거로 답한다로 정합니다. 단순히 “예쁘다” 또는 “원문과 많이 다르다”를 기준으로 삼지 않습니다.

| 작은 변경 | 학생 작업 | 비교·리뷰 질문 |
|---|---|---|
| A: 간격 | y 좌표 `1.2, 0.2, -0.8`을 `1.4, 0.2, -1.0`으로 바꾼다. x·z·radius는 유지한다. | 어떤 좌표가 높이를 정하는가? 공 사이 간격이 어떻게 달라졌는가? |
| B: 크기 | 최신 팀 버전을 바탕으로 radius `0.45, 0.45, 0.45`와 `0.55, 0.45, 0.35`를 비교한다. 좌표는 유지한다. | 색 이름을 말하지 않고 세 위치를 설명할 수 있는가? 크기가 겹침에 어떤 영향을 주는가? |
| C: 선택 비교 | 배경 또는 색 한 종류만 바꾸어 같은 시안을 비교한다. 새 API를 추가하지 않는다. | 위치·크기 효과와 색 효과를 섞어서 설명하지 않았는가? 어떤 조건을 고정했는가? |

선택 심화는 같은 문법으로 가로형 안내등을 만드는 정도로 제한합니다. y 세 값을 x 세 값으로 옮기고 나머지 축을 고정하는 전이 과제입니다. 반복문이나 시간 변화까지 한꺼번에 추가하지 않습니다. 소리는 이 경로의 필수 조건이 아닙니다. 소리를 덧붙이려면 다른 차시로 분리하고, 이 프로젝트의 좌표·크기 목표를 대체하지 않도록 합니다.

| 라운드 | 제공하는 도움 | 학생이 스스로 해야 할 일 | 다음 단계로 넘어갈 확인 |

## 원문과 기여를 어떻게 구분하는가

원문은 출처 제목과 ID, 시작 코드 v0로 확인할 수 있습니다. 이후 제안은 기준 버전과의 diff, 작성자, 검토자, 실험 근거를 보유합니다. 예를 들어 가의 y 좌표 변경과 나의 radius 변경은 작은 제안을 두 번 남기면 설명하기 쉽습니다. 교사가 대신 만든 기둥·기본 도형 생성까지 각 학생의 독립 구현으로 인정해서는 안 됩니다.

그러나 현재 UI의 diff는 **제안 기준 체크포인트와 제안 코드** 비교입니다. 차시 원문과 현재 코드의 전용 3자 비교는 없습니다. 데이터베이스의 v0를 별도로 열어 참고할 수 있지만, 원문 저자·콘텐츠 해시·수업목표가 PR 본문에 함께 전달되는 것은 아닙니다. GitHub PR은 작업 ID·기준 커밋·팀 체크포인트 정보를 중심으로 연결합니다. 최초 Issue 본문과 PR 설명에 다음을 사람이 보완하는 방식이 현재 운영안입니다.

```text
출발: beg-shapes / beg-shapes-4 / 신호등 만들기
기준: b45087dd42e8e6c588cf872465088674a5c5c54f
원문 목표: 세 sphere를 위·중·아래에 배치하기
교사 제공: import, 배경, 기둥, 세 도형 생성 골격
내 변경: y 좌표 3개만 변경. radius와 색은 유지
관찰: 전후 간격 차이, 예상과 달랐던 점
동료 질문과 응답: 질문·재실행 조건·유지/수정 이유
다음 적용: 같은 원리를 가로 배치에 적용
```

이 양식은 제안하는 수업 안내입니다. 현재 서비스가 자동 생성하지 않습니다. 공동 문제나 성공 기준의 수정 이력도 전용 버전으로 보존되지 않으므로, 목표가 바뀌면 새 Issue와 이유를 남기도록 합니다.

## AI 선택 사용과 미사용 수업

두 방식 모두 같은 짧은 코드, 같은 성공 기준, 같은 작성/검토 역할과 개별 설명 확인을 사용합니다. AI 사용 수업에서는 “서로 다른 좌표 간격 두 개를 제안해줘” 정도의 비교 도움을 허용하고, 학생이 채택한 값과 거절한 값의 이유를 남깁니다. 생성된 긴 이벤트 코드나 반복문을 이해하지 못한 채 붙여넣는 것은 목표 확장이 필요하다는 신호이며 높은 성취로 간주하지 않습니다.

AI 미사용 수업은 원문·동료 질문·교사 힌트만으로 전 과정을 수행합니다. AI 사용 여부 자체에 가감점을 두지 않고, 어떤 지원을 받았든 바꾼 값과 실제 결과를 설명하는지를 공통으로 봅니다. 현재 AI 정책 표시·선택적 사용 기록은 있으나 외부 AI 사용까지 기술적으로 차단하거나 사용 여부를 자동 검증하는 기능은 아닙니다.

개별 피드백 예시는 “가: y 좌표 변화와 간격을 연결해 설명했다. 다음에는 좌표를 고정하고 radius만 비교해보자”, “나: 동료 변경을 유지하며 radius 실험을 합쳤다. 크기 차이와 색 차이를 구분해 설명해보자”입니다. 교사 비공개 관찰에는 구두 설명에서 확인한 이해, 받은 도움, 다음 지원 계획을 쓰고 학생에게 줄 질문과 분리합니다.
