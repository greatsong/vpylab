# 새 교실 로컬 테스트 안내

브랜치: `codex/classroom-v2`. 기존 운영 서비스는 교체하지 않았습니다. 로컬에서 먼저 사용한 뒤 승인 여부를 판단할 수 있습니다.

## 실행

Node.js 22.16 이상에서 저장소 루트에서 실행합니다.

```sh
npm --prefix client ci
npm --prefix server ci
npm run dev:classroom
```

브라우저에서 [새 교실 열기](http://127.0.0.1:4043/classroom.html)를 선택합니다. 프론트는 4043, 서버는 4044를 사용하므로 기존 4033/4034 서비스와 구분됩니다. 첫 Python 실행 환경 준비에는 CDN 다운로드가 필요합니다.

설정이나 계정 비밀번호 없이 선생님·학생 가·학생 나로 입장할 수 있습니다. 이 계정은 이 컴퓨터의 로컬 테스트에서만 허용됩니다. 첫 실행에는 세 계정이 함께 참여한 예시 프로젝트가 생성됩니다. 화면 위의 ‘역할 바꾸기’로 다른 계정을 사용할 수 있습니다.

데이터는 `.local/classroom-v2.sqlite`와 브라우저의 계정별 초안에 남습니다. 서버를 껐다 켜도 프로젝트·초안·이력·검토가 유지됩니다. 로컬 모드는 실제 Supabase 데이터나 GitHub 저장소를 변경하지 않습니다. `Ctrl+C`로 서버와 프론트를 함께 종료합니다.

## 먼저 해볼 일

1. **선생님으로 입장**하여 예시 프로젝트를 엽니다. ‘제작과 실험’에서 실행 버튼을 눌러 3D와 출력을 확인합니다.
2. 코드를 바꾸고 ‘개인 초안 보존 완료’를 확인한 뒤 새로고침합니다. 작성한 초안이 다시 열리는지 봅니다. 아직 팀 버전은 바뀌지 않습니다.
3. ‘문제와 질문’에서 문제·성공 기준을 적고 수업의 AI 사용 방식을 선택합니다. **AI를 사용하지 않는 수업**으로 설정하면 기록 양식에 AI 사용란이 나타나지 않습니다.
4. 코드를 수정하고 ‘변경 제안’을 누릅니다. 제목과 예상·관찰·판단·다음 실험을 적습니다. AI 미사용 수업도 이 공통 기록만으로 진행합니다. 선택 수업에서는 AI를 사용한 경우에만 선택 기록을 남깁니다.
5. 오른쪽 위 계정 메뉴에서 **학생 나로 역할을 바꾸고** 같은 프로젝트를 엽니다. 이전 계정의 개인 초안이 보이지 않는지 확인합니다.
6. ‘함께 검토’에서 제안의 코드 차이와 실험 근거를 읽습니다. 검토 의견을 쓰고 승인한 뒤 팀 버전으로 반영합니다. 자신이 작성한 제안은 스스로 승인할 수 없습니다. 참여 교사는 검토 후 반영할 수 있습니다.
7. 이전 기준의 초안이 있으면 ‘팀에 새 버전이 있습니다’ 안내가 나옵니다. ‘최신 코드와 비교’로 두 코드를 확인합니다. 합친 코드 또는 최신 코드를 **개인 초안**으로 열며, 이전 내용은 ‘기록과 성찰’의 기기 복구 기록에 남습니다.
8. ‘팀 버전으로 저장’은 검토 없이 팀 버전을 직접 갱신하는 명시적 동작입니다. 기준 버전이 오래되면 거절됩니다. 기본 협업 흐름은 변경 제안과 동료 검토입니다.
9. 선생님으로 돌아와 ‘기록과 성찰’의 **피드백 작성하기**로 ‘GitHub 과정’에 들어가 피드백을 남깁니다. 공개 범위를 ‘대상 학생에게 전달’로 고르면 그 학생과 참여 교사에게만 보이고, ‘팀에 공유’를 고르면 팀 전체에 보입니다. 남긴 피드백은 ‘기록과 성찰’에서도 확인합니다.
10. ‘교사 관찰실’에서 프로젝트별 가설·관찰·다음 실험을 확인합니다. 저장 횟수를 기여도 점수로 환산하지 않습니다.

새 탭에서도 이전 창의 본인 초안을 복구합니다. ‘기록과 성찰 → 서버에 보존된 나의 초안’에서 다른 편집 창의 초안을 직접 열 수도 있습니다. 복원 전 현재 코드를 기기 복구 기록에 남깁니다. 여러 탭에서 역할을 바꾸면 이전 계정의 요청은 거절되고 작업 화면도 실제 계정으로 동기화됩니다.

AI 선택 수업은 외부 AI 도구의 제안과 자신의 검증·판단을 기록할 수 있는 방식입니다. 새 화면에는 내장 AI 채팅·자동 평가를 연결하지 않았습니다.

## 기존 수업 자료 사용

‘수업 자료’에서 기존 **7개 코스·46개 차시·54개 미션·57개 예제·71개 API 문서**를 읽을 수 있습니다. 검색과 분류를 제공하며, 미션에는 시작 코드·힌트·참고 풀이, API에는 속성과 예제가 표시됩니다.

‘이 자료로 프로젝트 만들기’를 누르면 원래 코드와 자료 출처를 가진 새 프로젝트를 만듭니다. 이미 열었던 프로젝트를 덮어쓰지 않습니다. 미션 프로젝트는 코드 실행 후 기존 채점 기준으로 학습 조건을 확인할 수 있습니다. 자동 확인 결과는 학생의 사고력 평가를 대신하지 않습니다.

수업 자료 분리 검사(새 교실 코드와 수업 자료 원본 5개가 같은 변경에 섞이면 실패, 기준은 `CURRICULUM_BASE` 환경 변수나 PR base 또는 직전 커밋. 의도한 동시 변경은 커밋 메시지에 `[curriculum]`을 넣어 허용):

```sh
node scripts/classroom/check-curriculum.mjs
```

## GitHub 연결 시험

‘팀·연결’의 기본 모드는 **로컬 모의 저장소**입니다. 실제 GitHub로 코드를 전송하지 않습니다.

1. ‘최신 GitHub 코드 가져와 비교’를 누르면 비교본을 가져옵니다. 개인 초안이나 팀 확정 버전은 자동으로 바뀌지 않습니다.
2. 팀 확정 코드를 변경해 새 버전으로 저장하고, 다시 ‘팀·연결’을 엽니다.
3. 비교본과 코드가 다를 때 제목을 적어 ‘팀 확정 버전을 GitHub PR로 제안’을 누릅니다.
4. 작업 대기열과 모의 PR 생성 상태를 확인합니다. 모의 PR은 실제 GitHub 링크를 만들지 않고 main도 변경하지 않습니다.

2026-10-28에는 별도의 실제 비공개 저장소에서 현재 GitHub CLI 로그인으로 Issue·PR·리뷰·코드 의견 수집과 피드백 공개 범위를 검증했습니다. 이 시험은 전용 DB와 4053/4054 포트를 사용합니다. [실제 GitHub 검증 결과와 실행 안내](CLASSROOM_V2_REAL_GITHUB_TEST_2026-10-28.md)를 참고합니다. `npm run dev:classroom`의 기본 모드는 계속 모의 저장소입니다.

실제 GitHub App 설치·JWT·설치 토큰 권한과 Webhook 실수신은 별도 검증이 필요합니다. 관련 설정과 권한은 [GitHub 연결 문서](classroom-github.md)를 참고합니다. 브라우저에 App 개인 키나 설치 토큰을 넣지 않습니다.

## 복구 시험

- `while True: pass`를 실행하고 정지합니다. 종료를 확인하기 전에는 재실행할 수 없으며, 응답하지 않는 Worker는 종료하고 다시 준비합니다.
- 실행 도중 다른 탭 활동이나 프로젝트로 이동한 뒤 돌아옵니다. 이전 실행이 계속 남지 않아야 합니다.
- 서버를 중지한 상태에서 편집하면 기기 보존 상태와 연결 실패가 표시됩니다. 서버를 다시 시작하고 연결을 재시도합니다. 브라우저 저장소까지 지우면 기기 초안은 복구할 수 없으므로 프로젝트 내보내기도 활용합니다.
- ‘코드 내려받기’는 Python 파일, ‘기록과 성찰 → 프로젝트 기록 내보내기’는 코드 이력·학습 증거를 포함한 JSON입니다. 개별 교사 피드백은 조회자 권한에 따라 포함됩니다.

백업과 임시 복구 리허설:

```sh
node scripts/classroom/backup.mjs rehearse --db .local/classroom-v2.sqlite
```

리허설은 임시 폴더의 복구본에서만 진행하며 원본 DB를 바꾸지 않습니다. 실제 운영 파일을 덮어쓰는 명령이 아닙니다.

## GitHub 과정과 교사 개별 기록

1. 선생님으로 예시 프로젝트의 **GitHub 과정**을 엽니다. ‘모의 협력 기록으로 살펴보기’를 누릅니다. 학생 가의 제안·학생 나의 리뷰·질문·대화·미연결 커밋이 표시됩니다. 실제 GitHub에는 쓰지 않습니다.
2. 관찰할 학생을 선택합니다. 왼쪽 기록에서 피드백 근거를 고르고 원문·시각·작성자를 확인합니다.
3. 기본 공개 범위 **나만 보는 교사 기록**으로 관찰을 저장합니다. 이 내용은 다른 교사·학생에게 보이지 않습니다.
4. 별도 피드백을 적고 **대상 학생에게 전달**을 선택합니다. 학생 가로 역할을 바꿔 해당 학생의 질문·근거·피드백이 보이고 교사 개인 메모가 없는지 확인합니다. 학생 나에게는 학생 가의 개별 피드백이 보이지 않습니다.
5. ‘기록과 성찰’과 프로젝트 내보내기에도 같은 공개 범위를 적용합니다. 최근 200개 밖의 원문 근거도 피드백의 제목·URL·SHA 스냅샷으로 보존합니다.
6. ‘문제와 질문’에 남긴 질문은 **이 질문을 GitHub Issue로 보내기**로 제출할 수 있습니다. ‘팀·연결’에서 팀 확정 버전을 PR로 제안한 결과도 GitHub 과정에 나타납니다.

작성 중 교사 메모는 기기에 교사·프로젝트·학생별로 임시 보존됩니다. 서버 저장 버튼을 누르기 전에는 전달되지 않습니다. 학생을 바꿔도 다른 학생의 메모에 섞이지 않으며, 돌아오면 해당 학생의 작성 중 메모를 다시 엽니다. GitHub 근거 선택은 제출 전에 다시 확인합니다.

운영 연동은 추가 Webhook 이벤트 구독과 검증된 GitHub 로그인 연결이 필요합니다. 수집이 부분적이거나 계정이 미연결이면 화면에 알립니다. 다음 질문은 기록을 살펴보기 위한 안내이며 자동 성적·능력 판정이 아닙니다.

## 동료 리뷰 시험

팀 간 동료 리뷰는 제안 승인 검토(‘함께 검토’)와 별개의 기능입니다. 설계 원칙 두 가지는 고정입니다. 배정은 교사가 하고, 형식은 “I like / I wish” 두 칸의 긍정적 피드백이며 점수·등급·승인 판정은 없습니다.

로컬 모드는 예시 프로젝트 외에 **학생 가 팀**(음악에 맞춰 빛나는 무대)과 **학생 나 팀**(천천히 도는 카메라와 행성)을 함께 시드합니다. 이미 있던 `.local/classroom-v2.sqlite`에도 서버를 다시 켜면 한 번만 추가되며, 동료 리뷰 테이블 3개(`peer_review_rounds`, `peer_review_assignments`, `peer_reviews`)도 기존 DB에 그대로 얹힙니다.

1. **선생님으로 입장**하여 ‘교사 관찰실’ 아래의 **동료 리뷰** 구역을 엽니다. 라운드 제목을 적고, 팀마다 검토할 팀 수(N)를 정한 뒤 학생 가 팀과 학생 나 팀을 체크해 ‘라운드 열고 배정하기’를 누릅니다. i번 팀이 i+1…i+N번 팀을 검토하는 순환 배정이 자동으로 만들어지며 어떤 팀도 자기 팀을 받지 않습니다. 팀 수가 N+1보다 적으면 가능한 만큼만 배정합니다.
2. 배정 표의 드롭다운으로 대상 팀을 바꿀 수 있습니다. 자기 팀, 라운드 밖 프로젝트, 중복 배정은 거부되고, 리뷰가 이미 작성된 배정은 바꿀 수 없습니다. 제출 현황 표에서 팀별 검토할 팀 수·쓴 리뷰·받은 리뷰를 봅니다.
3. **학생 가로 역할을 바꾸고** ‘학생 가 팀’ 프로젝트의 **동료 리뷰** 탭을 엽니다. 배정된 ‘학생 나 팀’ 카드를 누르면 대상 팀의 최신 저장본 코드·문제·성공 기준이 읽기 전용으로 열립니다. 교사 피드백, 개인 초안, 질문·제안은 보이지 않습니다. ‘실행해 보기’를 누르면 3D 화면에서 그 코드를 돌려볼 수 있고 저장은 할 수 없습니다.
4. ‘I like — 좋았던 점’과 ‘I wish — 이렇게 되면 더 좋겠어요’ 두 칸을 각각 20~1000자로 적고 ‘리뷰 보내기’를 누릅니다. 짧게 적으면 전송 전에 화면에서 알려주고, 서버도 같은 기준으로 거부합니다. 제출 뒤에도 자기 리뷰는 ‘리뷰 고쳐서 저장’으로 고칠 수 있습니다. 한 배정에 학생마다 리뷰는 하나입니다.
5. **학생 나로 역할을 바꾸고** ‘학생 나 팀’ 프로젝트의 동료 리뷰 탭에서 ‘받은 리뷰’를 봅니다. 작성자는 ‘학생 가 팀’처럼 팀 이름으로만 보이고 개인 이름은 교사만 봅니다. 배정되지 않은 프로젝트의 코드는 주소를 직접 열어도 403으로 거부됩니다.
6. 선생님으로 돌아와 라운드의 ‘작성된 리뷰’에서 작성자 이름을 확인하고 **라운드 닫기**를 누릅니다. 닫힌 라운드에는 쓰거나 고칠 수 없고(409), 받은 리뷰는 계속 볼 수 있습니다.
7. ‘GitHub 과정’에서 학생 가를 선택하고 ‘영역별 GitHub 근거 살펴보기’를 열면 동료 검토 영역에 **교실 안 근거: 동료 리뷰 1건**이 표시됩니다. 학생이 쓴 동료 리뷰는 협업 영역의 지역 근거로만 세며 GitHub 기록 건수와 섞지 않고, 점수로 환산하지 않습니다.

## 소리 들어보기

‘제작과 실험’의 **♪ 소리** 버튼을 열어 음량과 음소거를 바꿉니다. 소리는 코드를 실행할 때만 납니다. 예를 들어 `play_note("C5", 0.5, "piano")`를 실행한 뒤 **■ 정지**로 잔향과 예약된 연주가 정리되는지 확인합니다.

Python이 정상 반환해도 유한한 연주는 자연스럽게 마치며, 정지·오류·다음 실행·화면 이탈에서는 정리됩니다. 학교 기기의 실제 출력은 직접 들어보고 판단해주세요.
