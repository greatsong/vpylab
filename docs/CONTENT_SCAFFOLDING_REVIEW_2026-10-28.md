## 난이도를 낮게 유지하는 공통 설계

학생이 전체 코드를 모두 이해해야 한다고 요구하지 않습니다. 교사가 제공한 그래프·재생·물리 엔진은 유지하고, 이번 목표에 해당하는 값·식·조건만 학생에게 맡깁니다. 함수·리스트·중첩 반복도 선행 연습이 있다면 사용할 수 있습니다. 코드 줄 수를 줄이려고 한 줄에 여러 명령을 압축하거나 새 문법을 추가할 필요는 없습니다.

1. **예측:** 실행 전에 값·위치·음 순서가 어떻게 달라질지 말이나 그림으로 예상합니다.
2. **좁은 변경:** 처음에는 값 하나 또는 한 줄만 바꿉니다. 나머지 조건은 고정합니다.
3. **비교:** 원래 조건과 바꾼 조건을 같은 기준으로 관찰합니다. 오류·예상과 다른 결과도 기록합니다.
4. **설명:** 무엇을 바꿨고, 왜 결과가 달라졌다고 판단하는지 자신의 말로 설명합니다.
5. **도움 축소:** 같은 구조의 다음 문제에서는 완성 예시→부분 빈칸→질문만 남기는 순서로 지원을 줄입니다.
6. **전이:** 다른 값·장면·소리에서 같은 원리를 적용합니다. 참고 풀이를 보았다면 닫고 새로운 조건을 설명하게 합니다.

모든 단계마다 글을 길게 쓰게 하지 않습니다. 한 문장·두 조건 표·스케치·구두 설명으로도 근거를 남길 수 있습니다. 힌트를 열었다는 이유로 감점하기보다 지원을 줄인 마지막 활동에서 설명하고 적용하는지를 봅니다.

## 콘텐츠별 보완 설계

### 1. 도형·좌표 — `beg-shapes-1~5`, `CT-1/6`

- 교사 제공: import, 배경, 도형 호출 틀, 좌표축 그림, 속성 이름표.
- 학생 범위: 반지름 하나→색 하나→x좌표 하나. 다음 활동에서 두 도형의 간격을 직접 정함.
- 중간 질문: “반지름만 두 배면 중심도 이동할까?”, “x와 y 중 어느 값을 바꾸어야 위로 갈까?”
- 도움 축소: 완성 문장의 숫자 변경→속성 값 빈칸→두 도형 배치 설계.
- 전이 확인: 익숙한 공 대신 상자를 배치하고 위치·크기의 차이를 설명. 구의 radius와 상자의 size는 별도로 안내.

### 2. 반복·리스트·체스판 — `beg-patterns-1~4`, `CT-7/9/11`

- 전제: `beg-patterns-2`의 8회 반복·7색 인덱스 오류를 먼저 정정. 오류를 학생에게 갑자기 나머지 연산으로 우회하게 하지 않음.
- 교사 제공: i=0,1,2 추적표, 색 인덱스 표, 한 줄 반복 예시.
- 학생 범위: 개수만→간격만→색 목록의 한 요소. 리스트 만들기·객체 저장·두 번째 순회는 별도 단계로 분리.
- 선택 심화: 1행→2×2 격자→짝홀 표→조건 한 곳→8×8 체스판. 한 번의 반복과 if를 익힌 다음에 결합.
- 전이 확인: 다른 크기의 격자에서 개수와 색 규칙을 설명. 중첩 for·%·조건문을 동시에 처음 가르치는 필수 입문 활동으로 두지 않음.

### 3. 함수 — `CT-3/8`, `beg-patterns-6`

- 교사 제공: 함수 몸체와 첫 호출, 매개변수와 화면 결과의 대응 그림.
- 학생 범위: 호출 인자 1개→호출 2회 추가→함수 안 매개변수 연결 한 곳. 꽃의 삼각 좌표 내부 구현은 별도 선택 활동.
- 중간 질문: “호출 위치를 바꾸면 어느 도형들이 함께 움직일까?”, “함수 안의 값을 바꾸면 모든 호출에 어떤 변화가 생길까?”
- 전이 확인: 같은 함수로 다른 배치를 만들고 반복되는 부분과 달라지는 부분을 설명.
- 확인 기준: 결과 모양과 이번에 연습할 함수 사용을 분리. 정규식 일치도 함수 이해의 완전한 증거는 아님.

### 4. 수학·슬라이더·과학 모형 — `fus-math-2/3`, `fus-sci-1/5/6/7`, `SC-1~5`

- 교사 제공: 콜백·global·그래프·시간 루프·수치 모형. 시간 간격, 단위, 고정 조건, 단순화 가정도 함께 제공.
- 학생 범위: 기울기 또는 초기 높이 하나. 진자 길이·초기 속도 비교는 모형을 받은 선택 탐구로 운영.
- 중간 질문: 처음 세 시간 단계의 위치·속도 표를 채우고, 바꾼 변수와 고정한 변수를 구분.
- 도움 축소: 두 값 비교표 제공→측정할 값만 제시→학생이 비교 조건과 관찰 기준을 선택.
- 전이 확인: 새 계수의 결과를 예측하고 반례를 설명. 미분방정식 유도·콜백 전체 구현을 공통 성취기준으로 삼지 않음.
- 정확성 선행: rate와 모형 dt의 구분, v-t 기록 시점, 물리량 이름부터 정리. 재생 속도만 바뀐 것을 물리 법칙 변화로 해석하지 않게 함.

### 5. 미디어아트·격자·픽셀 — `MA-2`, `AR-1/2/6`, `AR-7`, `SC-6`

- 교사 제공: 좌표·삼각함수·이중 반복·애니메이션 엔진과 허용 패턴 표.
- 학생 범위: 색 한 묶음, 파도 높이 한 값, 0/1 패턴 한 줄. 작동 원리를 배우는 경로는 객체 하나→한 행→격자→시간 갱신으로 분리.
- 중간 질문: “같은 규칙에서 색만 바꾸면?”, “패턴의 이 칸은 화면의 어느 칸일까?”
- 도움 축소: 패턴 예시 제공→일부 빈칸→자기 규칙 설계와 설명.
- 전이 확인: 다른 크기의 패턴·색 규칙으로 의도를 전달. AR-7의 초기값 덮어쓰기, SC-6의 여러 곳에 흩어진 시작점은 제어점 정합성을 먼저 보완.

### 6. 멜로디·음색·음악 창작 — `beg-melody-1~5`, `SN-1/2/6/8/9/10`, `music-childrens-songs`

- 교사 제공: 허용 음 이름·길이·악기 목록, 짧은 재생 엔진, 음량·정지 방법. 긴 동요 데이터·버튼 콜백·lambda는 학생의 필수 작성 대상에서 제외.
- 학생 범위: 3~4개 음 순서 하나→길이 하나→같은 멜로디에서 음색만 변경. 고정 길이 단일 리스트 후 음/길이 표를 거쳐 두 리스트·zip으로 진행.
- 중간 질문: “같은 음 순서에서 길이만 바꾸면?”, “시작·변화·끝이 들리는가?”, “화면의 변화는 어떤 소리와 대응하는가?”
- 도움 축소: 선택할 음 제공→한 마디 빈칸→짧은 자기 멜로디와 선택 이유.
- 전이 확인: 다른 음·악기로 같은 리듬을 유지하고 판단 근거 설명. 예쁜 소리의 단일 정답을 정하지 않고 의도·균형·끝맺음·동료의 해석으로 피드백.
- 접근성: 소리를 듣기 어려운 환경에는 음 이름·순서·길이·시각 이벤트 표로 동일한 구조를 설명하는 경로 제공.
- 정확성 선행: 한글 반음과 문자열 화음 처리를 먼저 보완한 뒤 실제 출력·청감을 확인. 수업 코드가 맞지 않는데 학생의 감상 능력을 평가하지 않음.

## 기본 문법을 활용한 선택 심화의 허용 범위

체스판 규칙, 벽에서 방향 바꾸기, 색 패턴과 무작위 조합, 짧은 질문·응답 멜로디는 기본 문법을 조합하면서 사고를 확장하기 좋습니다. 해당 문법을 따로 경험한 뒤 선택 과제로 제공합니다. 필수 경로의 완료 조건을 복잡한 엔진 전체 재작성으로 높이지 않습니다.

삼각함수·중력장·콜백·lambda를 감추고 전체 작품만 “쉬운 코드”라고 소개하는 방식은 피해야 합니다. 제공된 모형을 조작하는 탐구와 모형을 구현하는 프로그래밍은 각각 다른 목표와 평가 기준을 갖습니다.

## AI 사용·미사용 및 GitHub 과정 기록

두 수업 모두 같은 예측·실험·설명·전이 기준을 사용합니다. AI 미사용 수업은 카드·부분 예시·짝 설명으로 진행할 수 있어야 합니다. AI 사용 수업은 최초 예상, 받은 제안, 채택·거절한 부분, 직접 비교한 결과를 기록합니다. AI가 더 긴 코드를 생성했다는 이유로 심화 성취로 판단하지 않습니다.

| 단계 | 남길 근거 | 교사가 볼 것 |
|---|---|---|
| Issue | 바꿀 변수, 예상, 고정 조건 | 문제를 이해하고 비교를 설계했는가 |
| 작은 PR | 바꾼 값·식·조건, 전후 결과 | 변경과 관찰 사이의 연결을 설명하는가 |
| 리뷰 | 동료의 이유 질문 또는 반례 | 결과를 보고 판단을 조정하는가 |
| 후속 변경·성찰 | 유지/수정한 이유, 새 조건 적용 | 도움을 줄인 뒤 다른 상황에도 적용하는가 |
| 교사 개별 기록 | 구두 설명·스케치·받은 도움 | GitHub에 남지 않은 활동까지 함께 해석하는가 |

모든 작은 연습마다 이슈·PR·형식적 리뷰를 강제하면 Git 사용 자체가 추가 부담이 됩니다. 초기에는 교사가 팀 저장소와 제출 틀을 준비하고, 대표 비교 실험을 묶어 기록합니다. 입력 담당과 설명 담당을 번갈아 맡기되 커밋 수를 개인 이해 점수로 쓰지 않습니다. 교사 개인 관찰은 공개 범위를 구분합니다.
