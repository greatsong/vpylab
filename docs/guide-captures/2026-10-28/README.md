## 자료의 출처와 범위

- 실제 두 GitHub 계정 시험 DB의 일관된 복사본을 별도로 사용합니다. 원본 시험 DB·운영 서비스·외부 GitHub에는 변경을 보내지 않습니다. 안내 복사본은 GitHub 외부 통신을 차단하고 작업 처리 worker를 시작하지 않습니다.
- 실제 GitHub의 PR #3, 동료의 검토 의견·승인과 기존 근거 원장의 ID·URL·작성자·SHA·원문은 보존합니다. PR #3은 열린 상태이며 병합 완료를 보여주는 자료가 아닙니다.
- 프로젝트 이름·문제·성공 기준과 합성 교사 피드백 6개는 복사본에서 안내용 문장으로 정리했습니다. 질문·로컬 변경 제안·로컬 동료 검토 각 1개도 복사본에만 추가한 합성 자료입니다. 이 추가 자료는 GitHub에 게시하지 않았습니다.
- Python 실행용 코드는 촬영 중 개인 초안에 입력한 안내용 코드입니다. 변경 제안 모달과 교사 메모의 입력 문장은 촬영을 위한 미제출 예시입니다.
- 학생 이름과 학습·피드백 내용은 합성 자료이며 실제 학생 개인정보·성적·비밀번호·토큰을 포함하지 않습니다. GitHub 계정명 `greatsong`과 `greatsong-danggok`은 사용자가 허용한 실제 시험 계정입니다.
- 교사 개인 메모는 합성 자료입니다. 학생 화면에는 교사 개인 기록과 상대 학생의 개별 피드백이 표시되지 않아야 하며, 두 학생 장면과 검증 기록에서 이 범위를 확인합니다.
- 입장 화면의 역할 선택은 로컬 시험 기능입니다. 실제 GitHub OAuth 로그인, GitHub App 설치, Webhook 수신을 검증한 안내로 사용하지 않습니다.

## 안내서에서 활용하는 순서

학생용 시작 안내는 **01 → 02 → 03 → 04 → 05 → 06** 순서로 구성합니다. 실제 서비스 로그인 안내가 따로 마련되면 그 뒤에 01을 배치하고, 00은 로컬 시험을 설명하는 부록에 둡니다.

협업 안내는 **07 → 08 → 09 → 11·12 → 13** 순서가 적합합니다. 07의 교실 안 승인과 08 이후의 실제 GitHub 리뷰를 구분하고, 11과 12는 작성자·검토자의 기록 귀속을 비교하는 한 쌍으로 사용합니다. GitHub PR이 승인됐다는 사실과 팀의 기본 브랜치에 병합됐다는 사실도 구분합니다.

교사용 안내는 **14 → 09 → 10 → 11·12** 순서로 구성합니다. 관찰실에서 프로젝트에 들어가 학생별 근거를 고르고, 교사 비공개 기록과 학생·팀에 전달할 피드백의 범위를 설명한 뒤 학생이 실제로 보는 화면을 보여줍니다.

인쇄물에서 일부를 잘라 사용할 때도 탭 이름·역할·공개 범위 배지와 필요한 설명은 남겨주세요. 화면의 합성 질문·메모를 실제 학생 사례로 소개하거나, 이 이미지 묶음을 실제 학생 사용성·음질·동시 수업 부하 검증의 증거로 제시하지 않습니다.

## 다시 촬영할 때

프로젝트의 `scripts/classroom/guide-preview.mjs`로 별도 복사본을 열고, 다른 터미널에서 `scripts/classroom/capture-guide.mjs`를 실행합니다. 설치된 Playwright 모듈을 자동으로 찾지 못하면 `VPYLAB_PLAYWRIGHT_MODULE` 환경 변수에 해당 모듈 파일 위치를 지정합니다. 사용자 브라우저 프로필이나 기존 로그인 정보를 가져오지 않습니다.
