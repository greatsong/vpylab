# 창작 교육자료와 VPython 호환 기준

> 최신 후속 검토: [도형 AI·compound·카메라·학습 이동 보고서](SHAPE_CAMERA_UX_REVIEW_2026-11-07.md). 이 문서의 이전 검증 수치와 구별해 보세요.


2026-11-06. 코딩이 처음인 중·고등학생을 대상으로 한 설계와 로컬 구현·검증 보고입니다. 운영 배포는 포함하지 않았습니다.

## 결정

**학생이 직접 모양과 표현을 바꾸고, 친구의 해석을 듣고 수정하는 가이드를 기본으로 합니다.** 학습 활동에 Solar 코드 생성·자동 오류 수정 호출을 추가하지 않았습니다. 교재를 설계하는 과정에서만 요청하신 Claude 검토를 사용했습니다.

특별한 논리적 문제가 없는 기능은 **표준 Python과 VPython의 인자·값·이벤트·좌표 의미**를 기준으로 구현합니다. GlowScript만의 JavaScript 확장 때문에 Python 내장 문법을 바꾸지 않습니다. 빛의 `emissive`, `local_light`는 VPython 기능이고, `play_note` 등 소리는 VPyLab 확장입니다. 반구의 `make_dome`은 파일 안에 포함한 제공 함수입니다.

공식 기준: [VPython 문서](https://www.glowscript.org/docs/VPythonDocs/index.html), [공유 정점과 텍스처 좌표](https://www.glowscript.org/docs/VPythonDocs/vertex.html), [canvas](https://www.glowscript.org/docs/VPythonDocs/canvas.html), [helix](https://www.glowscript.org/docs/VPythonDocs/helix.html), [VPython Python 구현](https://github.com/vpython/vpython-jupyter/blob/master/vpython/vpython.py). 설치형 VPython을 별도 구동해 전 화면을 대조했다는 뜻은 아닙니다.

## 메뉴와 학습 흐름

최상위 메뉴는 **튜토리얼 / 트레이닝 / 갤러리 / 만들기**입니다. `/missions` 주소와 기존 연습·학습 기록은 보존하고 화면 이름을 트레이닝으로 통일했습니다.

- 튜토리얼: 기존 3~5분 체험 4개. 그 아래 선택 활동인 **만들며 탐구하기** 3개를 제공합니다.
- 트레이닝: 기존 빛·소리 기초 8차시와 핵심 연습 6단계. 창작 활동으로 이어지는 링크를 제공합니다.
- 갤러리: 출처가 확인된 실제 작품과 교사 참고자료. 새 예제를 학생 작품으로 표시하지 않습니다.
- 만들기: 활동의 해당 단계 코드와 변경·성찰·동료 시험 안내를 함께 엽니다. 신호의 단계를 바꾸어도 올바른 시작 코드가 들어갑니다.

### 선택 활동

| 활동 | 시간·인원 | 출발 코드 | 학생이 결정하는 것 | 동료 시험 |
|---|---|---|---|---|
| 세 숫자로 나만의 모양 | 10~15분, 1~2명 | 타원체 두 개, 고정 카메라 범위 | 길이·높이·폭, 부품 위치, 표현할 대상. 최종 변형은 자유롭게 | 코드 없이 무엇으로 보이는지와 그 단서 |
| 나만의 신호 | 15~20분, 1~2명 | **모양 → 빛 → 소리**의 독립 실행 3단계 | 신호의 뜻, 크기·모양, 마지막에 선택한 음 높이·길이 | 소리 없이도 이전과 이후를 구분할 수 있는지 |
| 친구가 알아보는 팀 신호 | 25~35분, 2~3명 | 물체 하나와 상태 함수·버튼 두 개 | 상태의 의미와 모양을 약속표에 합의하고, 오해를 바탕으로 수정 | 뜻을 설명하기 전에 다른 팀이 해석 |

신호는 깜빡임 없이 상태를 유지합니다. 소리는 버튼 뒤의 짧은 음 한 번이며 기본 팀 예제에는 넣지 않았습니다. 소리를 사용해도 그 줄을 지우면 시각 표현이 남습니다. 색 하나만으로 뜻을 전달하지 않도록 크기·방향도 바꿉니다. `emissive=True`는 물체가 밝게 보이는 설정이며 주변 물체를 비추는 조명이라고 가르치지 않습니다.

### 반구는 선택 심화

`/tutorials/hemisphere`에서 `make_dome(radius=1, height=1, segments=16)`을 먼저 보여 줍니다. **반지름과 높이가 같으면 반구, 다르면 반타원체(돔)**입니다. 바닥은 닫혀 있습니다. 삼각형 메시가 곡면을 근사하며, 조각 수는 4~32 정수로 제한했습니다.

함수 전체는 펼쳐 볼 수 있고 실습 코드에 포함됩니다. 다른 VPython 환경에 옮길 때도 함수를 함께 복사합니다. 학생의 필수 목표는 숫자 세 개와 결과를 연결하는 것입니다. 삼각함수·법선 수식의 유도는 선택입니다. 구를 상자로 가린 모양을 실제 반구로 제시하거나, VPython에 원래 반구 명령이 있다고 설명하지 않습니다.

## 팀 수업 운영

1. `상태 | 전달할 뜻 | 모양·크기 | 소리(선택)` 약속표를 함께 작성합니다. 모두 아이디어 하나씩 냅니다.
2. 입력 담당과 예상·검토 담당을 나눕니다. 세 명이면 관찰·기록을 더합니다. 작은 수정 하나를 마치거나 8분이 지나면 교대합니다.
3. 기준 코드는 한 기기에서 관리합니다. 기존 프로젝트 패널의 초대·저장·항해 일지를 활용할 수 있습니다. 다른 기기에서는 최신 코드를 가져온 뒤 차례로 수정·저장합니다. 실시간 공동 타이핑 기능으로 안내하지 않습니다.
4. 다른 팀은 뜻을 듣기 전에 신호를 해석합니다. 만든 팀은 오해 한 가지를 골라 약속표와 코드를 함께 고칩니다.
5. 각자 `___가 ___로 오해되어 ___를 바꿨다`를 말하거나 주석·메모로 남깁니다.

교사는 기능을 많이 썼는지 대신 **변경한 줄과 결과를 연결하는지 / 동료의 의견을 실제 수정에 반영했는지 / 모든 팀원이 한 번 이상 결정과 편집에 참여했는지**를 관찰합니다. 발표는 주석·메모로 대체할 수 있습니다. 새 자동 점수·완료율·가입 절차는 추가하지 않았습니다.

예상→실행→살펴보기→변형→창작은 [PRIMM 연구 소개](https://www.raspberrypi.org/blog/primm-talk-in-programming-lessons-research-seminar/)와 [프로그래밍 교수 원칙](https://www.raspberrypi.org/teach/pedagogy)을 참고한 설계입니다. 이 VPyLab 자료의 학습 효과를 실제 학생 수업으로 실증했다는 주장은 하지 않습니다.

## 이번에 개선한 VPython 동작

| 영역 | 원인과 개선 | 확인 |
|---|---|---|
| 독립 canvas | 모든 호출이 같은 scene을 돌려주던 구현을 분리. 선택·명시적 canvas·객체 이동, 카메라·키/마우스 상태, 위젯·그래프·제목/캡션을 화면별로 연결 | 두 화면의 버튼·키 입력이 다른 물체를 바꾸지 않음. 두 번 실행해도 이전 화면이 남지 않음 |
| 캡션·제목 앵커 | 다른 화면을 선택한 뒤 `pos=a.caption_anchor`를 써도 a에 배치 | Python 명령의 대상 canvas 검사 |
| vertex와 triangle/quad | 공유 정점의 위치·법선·UV·색·투명도·광택·발광을 실제 geometry/material에 연결. 같은 프레임의 변경은 면당 최종 값 한 번 전송 | 두 면이 공유하는 정점 변경, 실제 WebGL 질감과 Rug 표면 변형 |
| 정점만 바뀌는 프레임 | heartbeat가 일반 커맨드만 검사해 메시 변경을 전송하지 않음 | dirty mesh도 rate마다 전송. 종료 전에 변형 두 번이 각각 전달되는 회귀 검사 |
| 텍스처 대기 | `scene.waitfor('textures')`를 완료할 이벤트가 필요 | 로딩 완료·실패 후 대기 해제. 이전 실행의 늦은 완료 이벤트는 버림 |
| helix | size 누락, radius 변경이 렌더링에 반영되지 않고 선 두께도 Line으로 표현 | 길이·두 단면 직경·axis/up·coils·ccw·thickness를 연결. 튜브 반지름은 thickness/2 |
| 마우스·카메라 | 문서의 `scene.mouse()` 호출형 미지원, 기본 fov 차이, 사용자 줌/회전/이동 설정이 값만 저장됨 | mouse 속성과 호출형 함께 지원. 기본 fov 60도, 각 canvas의 카메라 조작 설정 적용 |
| 실행 간 카메라 | 새 예제가 이전 예제의 중심과 시야를 물려받아 도형이 화면 밖으로 사라짐 | 새 실행에서 중심·방향·fov 초기화. 실제 Rug 표시와 카메라 회귀 검사 |
| 개발 모드 재초기화 | 보조 뷰포트의 첫 setup이 명령을 소비한 뒤 폐기되면 다음 setup은 빈 scene | 안정된 프레임에 준비 콜백 전달, 폐기 콜백 취소. renderer 해제 시 WebGL context도 반환 |
| 여러 화면의 자원 | 조명·billboard·삭제가 전역 객체에 영향을 줄 수 있음 | 캔버스별 조명·billboard 방향·삭제 범위 분리 |

기존 검사에서 VPyLab의 잘못된 단일 canvas 동작을 정답으로 삼던 자체 idiom도 독립 canvas 규칙으로 수정했습니다. 브릿지의 `if (cmd.action === ...)` 처리 역시 검사기가 읽도록 바꾸었습니다. 이를 하지 않으면 구현된 canvas 명령을 미지원으로 잘못 분류합니다.

## 유지한 예외와 한계

- Worker의 외부 코드 실행·네트워크·로컬 파일 접근 제한을 완화하지 않았습니다. `get_library`, `read_local_file`, `download`는 해당 경계를 지키는 별도 설계가 필요합니다.
- JavaScript 전역 `Date`·MathJax를 쓰는 GlowScript 예제와 Jupyter의 `ipywidgets` 데모는 Python/VPython 기본 API와 별도 호스트 환경입니다. 가짜 Python 이름을 추가하지 않았습니다.
- 소리·한글 별칭은 VPyLab 확장입니다. 테마 배경, 반응형 화면 크기·배치와 프로시저럴 텍스처는 원본과 픽셀 단위로 같다는 보장이 없습니다. canvas `align`·`resizable`의 데스크톱식 창 배치까지 재현한 것은 아닙니다.
- 공유 HTML의 위젯·그래프·이벤트·복수 화면 지원 범위는 편집기보다 좁습니다. 이번 팀 활동은 VPyLab의 프로젝트·코드 공유로 진행합니다. 독립 HTML과 편집기의 전체 API 동등성을 선언하지 않습니다.
- 정점의 bumpmap까지 원본과 동일하게 렌더링한다는 검증은 포함하지 않았습니다. helix 코일 수는 브라우저 자원 보호를 위해 절댓값 256 이하이며, 상한 초과는 오류로 설명합니다.
- 이 코퍼스가 전체 API를 다 포함하지는 않습니다. 초기 실행·화면 표시·상호작용을 구분하며, 설치형 VPython 전수 비교나 완전 호환이라는 표현을 쓰지 않습니다.

## 수업 적용 전에 판단하실 부분

필수 승인 없이 진행할 수 있는 범위는 구현했습니다. 실제 수업에서는 **팀 신호를 선택 활동으로 둘지, 공동 결과물 활동으로 운영할지** 정하면 됩니다. 첫 수업에는 짧은 체험과 나만의 신호까지, 팀 활동은 함수·버튼을 경험한 다음 시간을 권합니다. 학생들의 실제 결과물을 보고 활동 시간과 어휘를 조정하는 수업 검증은 남아 있습니다.
