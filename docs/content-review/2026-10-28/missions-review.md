## 판단 요약

변수·반복·조건·리스트를 짧게 수정하는 CT 미션, 색·위치·멜로디를 바꾸는 창작 미션은 사용자의 “코드는 어렵지 않게, 기본 문법을 조합하는 심화는 일부 허용” 기준에 활용할 수 있다. 완성 예제를 제공하는 방향도 적절하다. 다만 완성 예제의 긴 내부 코드를 학생이 모두 이해하거나 새로 작성해야 하는 것으로 제시하면 입문 난이도가 크게 올라간다. 특히 L1 표시의 SC-2, AR-1, AR-2, AR-6은 편집 전용 입문 경로와 내부 알고리즘 탐구 경로를 분리할 필요가 있다.

현재 채점은 학습 목표의 달성 증거로 충분하지 않다. 37개 튜토리얼은 모두 시작 코드와 참고 풀이가 같고 객체만 생성되면 실행형 채점에서 100점을 받는다. CT 17개의 결과 검사는 유용하지만, v2는 함께 선언된 문법 검사 14개 미션분을 적용하지 않는다. 실행 확인, 목표 조건 확인, 학생의 설명·전이를 구분해서 보고해야 한다.

전수 판정은 적합 17개, 보완후적합 23개, 선택심화 9개, 입문경로분리 5개다. 이 수치는 소스 검토에 따른 수업 편성 판단이며 학생의 실제 성공률을 예측하는 자동 점수가 아니다.

- 54개의 설명, 시작 코드, 참고 풀이, 힌트, assertions, codeChecks, gradeType을 모두 읽었다.

- 주 검토자가 실제 JavaScript 채점 엔진을 객체 레지스트리와 함께 격리 실행한 결과도 대조했다. 함수 없는 CT-3 결과의 gradeA 통과/codeChecks 실패와, 무관한 구 하나의 gradeRun 통과가 재현되었다. [재현 결과](/Users/greatsong/greatsong-project/vpylab/docs/content-review/2026-10-28/grading-sound-checks.json)는 Python 실행이나 학생 수행 실험을 뜻하지 않는다.
- 판정은 연령별 학습 실험, 실제 학생의 완료 시간·오류율, Pyodide 전체 실행, 실제 음질 청취 결과가 아니다. 소스에서 확인한 내용과 교수 설계에 대한 판단이다. 대상 학생의 학년·선수 경험이 제시되지 않았으므로 “Python 기본 문법을 배우는 초심자, 3D·음악 API는 교사가 제공”을 기준으로 삼았다.

표의 판정은 다음 뜻이다. 적합은 관련 선수 지식 수업 뒤 짧은 편집으로 수행 가능한 경우다. 보완후적합은 개념 설명·검사 기준·편집 경계를 보완해야 하는 경우다. 선택심화는 기본 문법의 복합 활용 또는 수학·물리 부하가 커서 필수 입문 경로 밖에서 선택하도록 권하는 경우다. 입문경로분리는 완성 엔진을 제공한 숫자·패턴 편집은 입문자가 할 수 있지만 내부 알고리즘 이해·작성은 별도 활동으로 나눠야 하는 경우다. 레벨 숫자만으로 판정하지 않았다.

| SN-9 · L3 | 보완후적합 | 사전 대응은 기본 문법 조합 심화로 적절하다. 색은 현재 음 높이 아닌 순서에 연결되며 허용 음 밖은 KeyError 위험이 있다. | 제공: 음·높이 대응표와 허용 음 목록. 학생: 기존 음만 순서 변경→대응 값 하나→새 음을 표와 목록에 함께 추가. |
| SN-10 · L3 | 적합 | 순차 호출과 객체 속성 변경만 사용해 작성 난이도는 높지 않다. 짧은 창작 결과와 설명 중심이 적절하다. | 제공: 악기·음·화음 호출 틀. 학생: 세 음→색 변화→마지막 화음 중 한 요소씩 고르고 기억할 특징 설명. |

## 별도 스캐폴딩 보완 설계

아래는 현재 구현되어 있다고 주장하는 기능이 아니라 수업 자료·활동지에 추가할 설계 제안이다. AI 없는 수업에서도 교사의 짧은 안내, 인쇄 카드, 짝 설명으로 수행하도록 한다. AI 허용 수업에서도 예상과 최초 시도는 먼저 기록하고, AI 제안 중 채택·기각한 이유와 직접 실행한 반례를 남긴다.

### S1. 공통 과정 증거: 예측 → 한 개 변경 → 설명 → 새 문맥 전이

교사는 실행 가능한 기준 코드, 이번 시간에 바꿔도 되는 1~3곳, 고정할 조건, 결과를 비교할 표 한 장을 제공한다. 학생은 (1) 실행 전 결과를 한 문장·스케치로 예상하고, (2) 한 값 또는 한 줄만 바꾼 뒤 실행하고, (3) 기존 결과와 달라진 점 및 원인을 자기 말로 설명하고, (4) 다른 입력·장면에서 같은 아이디어를 적용한다. 참고 풀이를 본 경우에는 풀이를 닫고 새로운 값으로 다시 설명하게 한다. 전체 코드를 암기해 다시 쓰게 할 필요는 없다.

GitHub 기록은 Issue에 예상·고정 조건, 커밋/PR에 실제 변경 1개와 관찰, 리뷰에 동료의 반례, 후속 커밋에 판단 수정으로 연결할 수 있다. 교사는 기록 수보다 이 네 단계 사이의 연결을 관찰한다. 한 학생이 말로 설명하고 다른 학생이 타이핑했을 수 있으므로 커밋 수를 개인 이해 점수로 바로 바꾸지 않는다.

### S2. 기본 문법: CT-1 → CT-6 → CT-7 → CT-12/13/14/15

교사 제공: 한 객체의 sphere 호출 틀, 변수와 속성의 대응 그림, for의 i 표, 조건 구간 표. 학생 작성: 처음에는 값 한 개, 다음은 변수 세 개, 다음은 range 숫자와 위치 식 한 곳, 다음은 분기 안 대입문이다. CT-1에서 키워드 인자를 처음부터 모두 작성하도록 요구하지 않는다. 조건 미션은 정답 색을 먼저 알려주는 대신 입력 2~3개를 예상하게 한 뒤, 틀린 분기를 찾도록 돕는다. CT-15는 CT-14와 동일한 사고를 네 구간으로 확장하는 선택 연습으로 운영해 반복 피로를 줄인다.

### S3. 함수·리스트: CT-3 → CT-8, CT-11 → CT-16 → CT-10 → CT-5

교사 제공: 함수 몸체와 첫 호출, 빈 리스트와 객체 생성 반복, 한 객체 위치 업데이트 예시. 학생 작성: 인자 추적표→호출 2회→매개변수 연결 2곳, 이후 색 인덱스 1곳→append 1줄→두 리스트 연결 1줄→시간 반복 속 같은 갱신 1줄 순이다. CT-5에서는 새 문법을 더하지 않고 이미 쓴 갱신을 반복한다는 점을 강조한다. 다음 미션에서는 인자 추적표나 빈칸을 하나씩 줄여 스스로 판단할 범위를 넓힌다.

### S4. 완성 엔진과 편집용 입문 경로: MA-2, SC-2, AR-1, AR-2, AR-6

교사 제공: 수학·물리·격자·애니메이션 내부 코드와 “오늘 설명하지 않아도 되는 부분” 표시. 학생 작성: MA-2의 꼭짓점수 하나, SC-2의 중력 목록 중 한 값, AR-1의 색 묶음 또는 변화 폭 하나, AR-2의 파도 높이 하나, AR-6의 0/1 패턴만이다. 학생이 바꿀 곳을 찾느라 전체 코드의 모든 식을 해석하지 않도록 한다. 엔진 작성을 배우는 선택 경로는 객체 하나→한 줄 반복→격자→시간 갱신 순으로 별도 분리한다. 입문 활동 통과를 엔진 내부 구현 숙달로 기록하지 않는다.

### S5. 과학 탐구: SC-1~5와 MA-3·7

교사 제공: 모의 시간·단위·고정 조건·초깃값·모델 한계를 포함한 실험 표. 학생 작성: 가설 한 문장과 변수 한 값, 관찰 수치 또는 동일 시점의 스케치, 가설을 유지/수정한 이유다. SC-1은 같은 모의 시간의 이동 거리, SC-2는 지면 도달 순서, SC-3은 첫 반등 최대 높이, SC-4는 진폭이 줄어드는 경향, SC-5는 궤적 형태를 비교한다. dt/rate와 sleep을 물리량으로 혼동하지 않도록 교사가 구분한다. 계수 여러 개를 동시에 바꾼 결과를 인과관계 증거로 쓰지 않는다.

### S6. 제어점이 어긋나는 자료: AR-7, SC-6, SN-9

교사 제공: AR-7은 초기 높이와 반복 중 높이의 차이, SC-6은 시작점 단일 변수와 단순 색 확산 가정, SN-9는 허용 음과 높이/색 대응표다. 학생 작성: 바꾸려는 의미 하나를 고르고 어느 변수에 연결되어야 하는지 먼저 표시한 뒤 한 값을 변경한다. 현재 자료 그대로라면 AR-7의 높이 목록 변경, SC-6의 시작점 한 곳 변경, SN-9의 음 높이에 따른 색 비교는 약속한 효과를 보장하지 못한다. 이 세 항목은 제어점 보완 후 학생이 자율 변형하도록 한다.

### S7. 소리·창작: SN-1/2/6/7/8/10, AR-4/9

교사 제공: 허용 음·악기·효과음 목록, 짧은 재생 길이 범위, 음량 조절 방법, 시작/변화/끝의 3칸 스토리보드. 학생 작성: 소리 한 요소만 먼저 바꾸고 같은 코드에서 다시 듣는다. “예쁘다”의 단일 정답 대신 의도한 분위기, 시작·끝의 분명함, 화면과 소리의 대응, 동료가 실제로 알아들은 특징으로 피드백한다. 두 번째 시도에는 교사 선택지를 줄이고 학생이 자신만의 기준 하나를 더 정한다. 청각 접근이 어려운 학생은 음 이름·지속 시간·시각 이벤트 표로 패턴과 선택 이유를 표현할 수 있어야 한다. 실제 음량·클리핑·음질 평가는 별도의 청취 확인이 필요하다.

### S8. 힌트의 단계와 지원 축소

교사 제공 힌트의 순서는 ① 예상과 실제가 다른 지점 질문, ② 바꿀 줄/속성 위치 표시, ③ 값만 비워 둔 한 줄 예시, ④ 완성 예시와 해설이다. 처음 문제는 ②까지 기본 제공하고, 유사 문제에서는 ①만 제공하며 ②~④는 요청 시 열게 한다. 학생 작성은 매 단계 “이번에 바꾸려는 값/이유” 한 문장이다. 힌트를 열었다는 이유로 점수를 깎기보다 마지막 새 입력에서 독립적으로 설명·수정할 수 있는지 확인한다.

## AI 없이도 가능한가

현재 미션의 Python 실행과 모든 핵심 과제는 AI 호출을 전제로 하지 않는다. 적합 항목은 API 카드와 선행 수업을 제공하면 AI 없이 수행 가능하다. 보완후적합·입문경로분리 항목은 위의 편집 경계와 관찰 표가 준비되어야 교사의 실시간 코드 대필에 의존하지 않는다. 선택심화는 학생이 원하면 도전하도록 제공하되, 필수 성취 기준을 복잡한 엔진 재작성으로 높이지 않는다.

평가는 AI 사용 여부와 무관하게 동일하게 적용한다. 실행 성공은 기능 확인, 바꾼 줄과 관찰의 연결은 설명 증거, 새로운 입력에 대한 예측·반례는 전이 증거다. 실제 학생 수행을 관찰하기 전에는 이 설계 제안만으로 교육 효과가 입증됐다고 말할 수 없다.
