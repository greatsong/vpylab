# 세 팀 프로젝트 교육적 적절성·스캐폴딩 검토

검토일: 2026-10-28. 대상은 `demos/month-projects/{original,course,remix}`의 최종 Python 코드, 각 8개 실행 스냅샷, `learning.json`, 출처·라이선스 파일이다. 수업 코드 확장 제작을 맡은 병렬 에이전트가 공통 기준으로 세 팀을 교차 검토했다. 외부 교사나 외부 AI의 독립적 효과 검증은 아니다. 실제 브라우저·GitHub 검증은 별도 실행 보고서로 확인해야 한다.

## 판정

**교사가 장면·입력 골격을 제공하는 2인 팀의 8차시 프로젝트로는 조건부 적합하다. 정규 정보 수업을 마친 학생에게 최종 코드 전량을 백지에서 작성하게 하면 난도가 높다.** 세 팀 모두 기본 문법으로 만든 의미 있는 완성품이며 단순 예제를 길게 복제한 결과물이 아니다. 다만 상태, GUI 사건 처리, 여러 리스트의 대응을 동시에 다루므로 정보 수업 이수만으로 자동으로 쉬워지지는 않는다.

가정은 4주 × 주 2차시 × 차시당 50분, 학생 2명이다. 실제 한 달이나 실제 학생의 성취를 검증한 자료는 아니다. 프로젝트 규모와 학습 기회를 판단했으며 학습 효과·공정한 개인 평가까지 입증하지 않는다.

문법은 대체로 변수·조건·반복·리스트·함수 범위다. 그러나 다음은 기본 문법 조합이어도 인지 부담이 크다. 행 번호는 최초 검토본 기준이며 이후 수정 시 함수 이름으로 다시 확인한다.

## 8차시의 발전과 난도 급증

실행 스냅샷은 실제로 발전한다. 창작은 공간→여러 사람→이동→대기열→전략→조작→자동 비교→음형, 수업 확장은 원본→8색→16박→제어→편집→변형→실험·음색→비교·초기화, 리믹스는 원작→평면 반사→범퍼→8음→모드·배치→접근성→재생→반례 수정의 흐름이다.

| 구간 | 최초 검토본 변화 | 수업 운영 조건 |
| --- | --- | --- |
| 창작 5→6차시 | 71→232줄, 함수 0→10개 | 큰 점프. 장면·위젯·라벨·초기화 골격 제공. 학생은 `prepare`, 시작/정지와 조건 잠금 핵심 수정 |
| 수업 확장 6→7차시 | 94→207줄, 함수 9→13개 | 장면·음 구슬·통계·음색이 동시 증가. 표현 코드는 제공하고 `beat_seconds`, 세 모드 차이와 음량 선택을 맡김 |
| 리믹스 4→5차시 | 68→275줄, 함수 2→14개 | 가장 큰 점프. UI 전량을 한 차시 자작 목표로 삼으면 부적합. 모드·배치 골격에서 조건과 보존 규칙을 완성 |

모든 팀에게 8차시 안에 모든 확장을 강제하지 않는 편이 좋다. 필수 완성 기준은 **한 핵심 기능, 한 조건씩 바꾼 비교, 반례 한 개에 대한 수정, 동료 재현, 출처·도움 기록**이다. 자동 비교의 모든 통계·3D 장식·추가 음색·도전 점수는 선택 확장으로 둘 수 있다. 전시 완성품은 노력한 팀의 상위 예시이며 모든 학생에게 동일한 양을 요구하는 최소 기준이 아니다.

## 스캐폴딩 별도 판정

세 `learning.json` 모두 단계별 지원과 철회, 질문·예상·관찰·판단·다음 질문·제안·동료 검토를 담았다. 최초 검토에서 실제 부분 구현본이 없다는 조건을 지적했고, 이후 아래 세 학생용 골격을 추가했다. **세 골격은 교사 제공 장면·UI가 실행되고 학생 핵심 함수 세 개를 미완성으로 남기는 실제 자료다.** 학생용 부분 구현본과 교사용 완성 예시를 구별할 수 있게 되었다.

| 수준 | 적절한 제공 | 학생에게 남길 사고 | 철회 기준 |
| --- | --- | --- | --- |
| 기본, 1~3차시 | 실행되는 짧은 출발 코드, 좌표/인덱스/상태 그림, API·원작 출처 카드 | 먼저 예측하기, 같은 인덱스 찾기, 기본 관찰 | 동료가 같은 조건으로 재현 |
| 표준, 4~6차시 | 사건 연결 골격, 반사 도움 함수, 빈 비교표·리뷰 질문 | 규칙·자료·조건 선택, 예외, 보존/초기화, 반례 | 실패 조건·수정 이유를 직접 설명 |
| 선택 심화, 7~8차시 | 최종 인수 조건과 필요 시 표현 코드 | 총시간/평균대기 차이, 평균 음높이 한계, 경계·접근성 | 다른 팀 재현·반론에 근거로 답함 |

실제 수업에서 유지할 원칙:

1. **교사 제공 범위**: 반사 함수뿐 아니라 UI·표현 골격도 이름으로 기록한다. 제공 코드를 학생 개인 성취로 계산하지 않는다.
2. **점진적 철회**: 처음에는 입력 후보·문장 틀, 나중에는 실패 조건만 준다. 마지막까지 정답 코드·정답 관찰을 주면 사고 과제가 따라 쓰기로 바뀐다.
3. **이중 자료**: `main.py`·`milestones`는 교사용 완성 예시, 아래 `scaffolds`는 학생용 부분 구현본이다. 완성 스냅샷을 학생용 골격과 동시에 정답으로 주면 탐색 여지가 작다.
4. **역할 교대**: 구현/검토 역할을 2차시 단위로 바꾸고 각자 코드 설명을 받는다. PR 수·코드 줄 수로 시각 설계·실험·반례 검토 기여를 낮게 평가하지 않는다.
5. **AI 선택성**: 세 프로젝트는 AI API 없이 실행된다. AI 허용 시 받은 도움·직접 검증을, 미사용 시 수업 예제·도움말·동료 도움을 기록한다. AI 여부 자체를 성취 점수로 삼지 않는다.

행은 2026-10-28 골격 바이트 검증본 기준이다. 함수 본문의 `학생 과제` 주석부터 바꾼다. `global` 선언·그래픽 생성·콜백 연결·전처리 내부는 교사가 제공하며 학생이 원리 없이 재작성하게 하지 않는다. 골격의 200여 줄을 학생 작성량으로 집계하지 않는다.

제공 코드 안의 안전한 `return`·`pass`는 정답이 아니다. **골격이 오류 없이 실행된다는 검사는 학생 과제를 완성했다는 판정이 아니다.** 최초 화면과 출력은 미완성임을 명시한다.

### 수준 선택과 지원 철회

- **기본**: 창작은 `move_person`을 도움 함수에 연결해 먼저 움직임을 만들고 두 출구의 번갈음 배정까지만, 수업 확장은 음/쉼표 편집과 원본 재생까지, 리믹스는 충돌 횟수·음 번호 기록까지만 필수로 삼는다. 교사는 사건 연결과 표현 코드를 계속 제공한다.
- **표준**: 세 TODO를 모두 완성하되 한 함수씩 예상→구현→두 경계값→동료 재현 순서로 진행한다. 창작은 사람 0/1과 5/6, 수업 확장은 박 0/15와 쉼표, 리믹스는 기록 0/7/8개와 모드/배치 초기화를 확인한다.
- **선택 심화**: 기본 기능을 통과한 팀만 자동 비교, 모든 쉼표·역순 편집, 45초 도전과 빠른 충돌 반례를 확장한다. 원형 반사 수식 유도·새 클래스·외부 라이브러리를 필수로 올리지 않는다.

처음에는 함수 주석과 입력·출력 예시를 유지한다. 학생이 두 경계 사례를 설명하고 동료가 재현하면 숫자 후보와 문장 틀을 거둔다. 다음 차시에는 정답 함수를 주지 않고 실패 사례만 제시한다. 마지막에는 완성 예시와 비교해 다른 구현의 타당성을 설명하고, 제공된 코드·자기 수정·동료 도움을 각각 기록한다. 평가 대상은 세 함수의 줄 수가 아니라 규칙 선택·예측·검증·반론에 대한 수정이다.

## 음악·색·설명의 적절성

음악은 장식에 그치지 않는다. 창작팀의 반복/번갈음/넓은 박자 음형은 전략을 기억하는 단서, 수업팀의 음높이·음색·박 길이는 실험 조건, 리믹스팀의 충돌 순서는 재생 가능한 8음 자료다. 수업팀의 선율 0.15·화음 0.06, 리믹스팀의 짧은 0.16 음과 발생 간격 제한, 창작팀의 무음 기본·짧은 진행음은 소리 겹침을 줄이는 의도가 보인다. **API 진폭 설정은 물리적 음압 측정이나 청력 안전·음질 보증이 아니다.** 소리의 아름다움은 실제 기기에서 청취 피드백을 받아야 한다.

색은 상태·음 이름/높이·범퍼 번호와 연결되고 숫자·라벨·그래프가 보완한다. 색↔음은 설계자가 정한 약속으로 명시해 보편적 감정·물리적 동일성을 주장하지 않는다. 수업팀의 평균 주파수는 합성음 조건 요약이며 음악의 좋고 나쁨 점수가 아니다.

창작팀의 직선 이동·같은 속도·충돌 없음·일정 처리 가정과 실제 안전 예측이 아니라는 한계가 적절하다. 출발 전 시차는 평균 출구 대기에 포함하지 않으므로 총시간도 읽게 한 점이 좋다. 리믹스는 현실 핀볼 물리 전체를 재현한 도구로 설명하지 않는다. 다만 리믹스의 '진행 배율'은 현재 코드상 관찰 시계보다 공 이동 속도를 배율로 바꾸므로, 수업에서 '속도 배율'로 설명해야 시간 가속과 혼동하지 않는다.

## 구현 검증과의 연결

최초 검토에서 창작·리믹스의 `global` 콜백 상태와 비동기 래핑 사이 실행 범위 문제를 발견해 제작 담당에게 전달했다. 두 담당은 상태 선언을 수정한 뒤 **실제 `preprocessCode` 출력 실행에서 해결을 확인했다.** 창작의 [callback-runtime-validation.json](../../../demos/month-projects/original/callback-runtime-validation.json)은 최종본과 6~8차시의 시작·정지·계속·초기화·완료를, 리믹스의 [processed-validation.json](../../../demos/month-projects/remix/processed-validation.json)은 모든 단계의 전처리 실행 및 최종본의 8음 완성·모드/음소거·45초 종료·재생을 기록한다. 이 결과는 CPython과 JS 전송 대체 또는 테스트 더블에 대한 검사이며, 실제 Pyodide·DOM·Web Audio 브라우저 검증은 루트가 별도로 진행한다. 실행기 래핑 내부를 학생 학습 부담으로 전가하지 않는다.

수업 확장팀은 실제 `vpython-api.py`에 대한 AST·입력·프레임 계약 18개, 전처리 9개 프로그램 파싱, 원본 일치를 확인했다. 이는 브라우저 렌더링·실제 청취·학생 학습 검증을 대체하지 않는다. 최종 판단은 위 교육 조건과 별도 실행 결과를 함께 읽는다.

추가한 세 골격은 [scaffold-validation.json](scaffold-validation.json)에 파일별 SHA-256·바이트·행 수를 기록했다. 실제 `preprocessCode`와 실제 `vpython-api.py`에 올려 각 130회의 대기 없는 비동기 프레임과 주요 위젯 콜백을 실행했다. 세 파일 모두 AST·전처리 파싱, 장면/위젯 생성, 안전한 미완성 반환값과 입력 호출을 통과했고 전처리 경고는 0개다. 원래의 최종 코드·8개 단계·학습 JSON은 두 골격 생성 전후 바이트가 바뀌지 않았음을 확인했다. 이 추가 검증 역시 실제 브라우저·청취 검사와 구별한다.
