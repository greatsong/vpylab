`file://`로 HTML 파일을 직접 열지 않고 위 HTTP 주소를 이용한다. Python 준비 후 **▶ 실행**을 누르면 오른쪽에 작품 조작부가 나타난다. 작품 속 조작부와 공통 음량·음소거를 함께 사용할 수 있다. 음향은 뮤직박스·피아노 등의 Web Audio 합성음이며 AI API 없이 실행된다. 최초 Python 준비에는 외부 실행 엔진 다운로드가 필요하다.

각 작품은 8차시의 서로 다른 실행 코드, 질문·가설·관찰 예시·판단·동료 검토·다음 실험을 제공한다. 차시 버튼으로 중간 코드를 고른 뒤 다시 실행할 수 있다. **정규 정보 수업 이후 2인 팀이 4주 동안 8차시를 진행한다는 합성 예시이며, 실제 학생 활동·한 달 경과·교육 효과를 측정한 자료는 아니다.**

## 실제 GitHub 협력 과정

사용자가 승인한 비공개 저장소 `greatsong/vpylab-private-classroom-e2e-20261028` 한 곳에서 기존 로그인 두 계정 `greatsong`·`greatsong-danggok`을 사용했다. 학생 가·나는 합성 역할이고, 실제 숫자 GitHub ID로만 귀속했다. 로그인 이메일로 학생을 추정하지 않았다.

| 팀 | 문제 정의 | 완성 코드·단계 커밋 | 다른 계정 검토 |
| --- | --- | --- | --- |
| 창작 | [Issue #4](https://github.com/greatsong/vpylab-private-classroom-e2e-20261028/issues/4) | [PR #5](https://github.com/greatsong/vpylab-private-classroom-e2e-20261028/pull/5), 8차시+화면 QA 2개 = **10커밋** | 마지막 표시 수정까지 최신 SHA 재승인 |

| 리믹스 | [Issue #8](https://github.com/greatsong/vpylab-private-classroom-e2e-20261028/issues/8) | [PR #9](https://github.com/greatsong/vpylab-private-classroom-e2e-20261028/pull/9), **8커밋** | 최신 SHA 의견·승인 |

Issue는 완료 처리했고 PR은 검토 가능한 열린 상태로 유지했다. main은 변경·병합하지 않았다. 8차시별로 로컬 변경 제안 → 다른 학생 검토 → 팀 저장본 반영 → GitHub 커밋·진행 의견을 실제로 진행했다. 작성자와 검토 역할을 교대했으며 본인 승인·승인 전 반영·오래된 초안 저장이 거절되는지 확인했다. 변경 요청 후 승인으로 바꾸는 과정도 포함했다.

최종 읽기 전용 재검증에서 세 PR의 현재 코드가 로컬 완성본과 일치하고, 다른 계정의 승인이 각각 같은 최신 SHA를 가리키는지 확인했다. [공개 가능한 합성 검증 요약](github-verification.json)에 원문 링크·숫자 계정·커밋·승인을 보존한다. 비공개 GitHub 원문은 저장소 접근 권한이 필요하다.

### 피드백·교사 개인 기록

- 같은 시험 저장소를 쓰는 세 팀의 Issue·PR·그 하위 커밋·리뷰·대화를 프로젝트별로 구분해 수집했다. 다른 팀 기록이 섞이지 않는 회귀 검사도 추가했다.
- 미병합 PR 커밋도 가져와 두 학생의 실제 작성자 숫자 ID에 연결했다. 실제 GitHub 작성자와 교실에서 제출을 요청한 학생을 구분한다.
- 각 학생에게 본인 근거가 연결된 개별 피드백과 교사 개인 관찰 기록을 각각 저장했다. 학생의 상세 조회·내보내기·학습 근거에서 교사 개인 기록과 다른 학생의 개별 피드백이 노출되지 않는지 확인했다.
- 학생이 다른 학생의 개별 학습 근거 URL을 요청하면 403으로 거절했다. 토큰은 메모리에만 보관하고 시험 DB·상태 파일·응답에 들어가지 않았는지 확인했다.
- 교실의 **협력 과정·개별 피드백** 링크에서 역할을 선택해 이 기록을 살펴볼 수 있다. 로컬 역할 선택은 실제 GitHub OAuth 로그인 검증과 구별한다.

최종 새 브라우저에서도 [교사 화면](screenshots/collaboration-01-teacher.png)과 [학생 피드백 화면](screenshots/collaboration-02-student-feedback.png)을 촬영했다. [협업 화면 검증](collaboration-browser-validation.json)에서 최신 승인 SHA와 학생의 비공개 기록 미노출을 다시 확인했다. 이 캡처는 로그인 외의 변경 요청을 차단한 상태에서 진행했다.

기존 CLI 인증을 이용한 로컬 검증이다. GitHub App 설치·실제 학교 OAuth 가입·Webhook 실수신·동시 다수 학급·운영 부하를 검증했다는 뜻은 아니다. GitHub 기록 건수를 성적이나 사고력 점수로 사용하지 않는다.

## 교육·스캐폴딩 별도 검토

[교육·스캐폴딩 검토 보고서](educational-review.md)는 코드 난도, 8차시별 발전, 난도 급증 구간, 교사 제공 범위, 학생 핵심 과제, 지원 철회, AI 선택 사용과 미사용 수업을 따로 평가했다.

판정은 **교사 제공 장면·입력 골격을 사용하는 2인 팀의 8차시에는 조건부 적합**이다. 최종 코드를 처음부터 전량 작성하게 하면 과하다. 학생이 채울 핵심 함수 세 개를 남긴 실행 가능한 미완성 골격을 팀별로 제공했다. 완성본과 골격은 전시 화면에서 각각 다운로드할 수 있다. [골격 검증](scaffold-validation.json)은 실제 전처리와 Python API에서 세 골격의 130프레임·입력 안전성을 확인했다. 제공 코드를 학생 개인 성취로 집계하지 않는다.

공개 리믹스는 공식 `vpython/vpython-jupyter`의 MIT `Bounce.py`, 고정 SHA `3254f6e4b845fdf27d8730b66887a9806d1822b3`를 출발점으로 삼고 원문·허가 문구·저작자·변형 범위를 보존했다. 원형 범퍼 반사 함수는 교사 제공이다. 색과 음높이는 설계한 대응 관계이며 같은 물리량이라는 주장을 하지 않는다. 창작 모델은 실제 재난 안전 예측용이 아니다.

## 다시 열기

현재 이 컴퓨터에서 작품 전시 4083, 협력 기록 API 4084, 이 보고서 허브 4085를 실행한다. 서버를 종료한 뒤에는 프로젝트 폴더에서 두 터미널로 아래를 실행한다. 이미 실행 중인 서버에 중복 실행하지 않는다.

```sh
node scripts/classroom/month-projects.mjs --serve
```

```sh
cd client
CLASSROOM_PREVIEW_PORT=4083 CLASSROOM_API_PORT=4084 node node_modules/vite/bin/vite.js --config vite.month.config.js
```

완료된 시나리오에서 `node scripts/classroom/month-projects.mjs --run`은 새 Issue·PR·커밋 없이 최종 코드·승인·커밋을 읽기 재확인한다. 브라우저 재검증은 `VPYLAB_PLAYWRIGHT_MODULE`에 설치된 Playwright 모듈 경로를 지정하거나 일반 `playwright` 모듈을 설치해 실행한다. 재실행 중 산출물 파일을 변경했다면 전시 프론트를 재시작해 변환 캐시를 갱신한다.
